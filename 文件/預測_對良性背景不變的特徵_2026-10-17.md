## 〇、為什麼做這一項，而不是別的

這是**唯一有量測支撐、而且離線動得了**的槓桿。支撐有兩條，都不是推論：

1. **C2C-124 的 E2**：把 `dataset_mega` 限制在**單一 3 小時批次窗**裡，它的類別
   幾何**等於** `refresh 640` 的 —— enforce 比值 **1.9983 對 1.9234**、
   permissive **2.177 對 2.141** —— 而 `refresh 640` 在那個幾何下 RF 拿
   **1.0000（P）／0.6851（E）**。
   ⇒ **資訊在裡面，被跨批次的良性背景蓋掉了。**
2. **C2C-125**：era 位移是真的（**20／20** 個類別的比值 > 1.3），而且
   **量體控制之後仍在**（≤0.1 dex 層 1.667；E4↔E6 的 ≤0.1 dex 子集 **1.8876**，
   n=780）。

而下列路徑已被量測關掉，所以不走：超參數（C2C-064）、問題表述（C2C-065，已採用）、
24 個學習器（C2C-066，前七名寬度 0.02 = 雜訊地板）、序列模型（六次比較零次領先）、
**同批次內加更多資料**（C2C-116：方向相反）。

## 一、統計量（四個，刻意做成可分解的階梯 ＋ 一個決定性的對照）

批次 id 取自 P0（`security_mode` 或 `code_revision` 改變、或 gap > 30s）。
令 `B(s)` 為場次 s 所屬的批次，`N(b)` 為批次 b 內**合格的 `normal_patrol` 場次**。

```
V0  原始特徵                                      ← 基準（C2C-124 量到 P 0.5124 / E 0.4040）
V1  x_j(s) − med_j( N(B(s)) )                     ← 只做批次內中心化
V2  ( x_j(s) − med_j(N(B(s))) ) / ( MAD_j(N(B(s))) + eps )   ← 中心化 ＋ 尺度
V3  x_j(s) − med_j( 全部合格 normal 場次 )          ← ⭐ 全域中心化（決定性對照）
```

**為什麼 V3 是決定性的**：若 V1 贏 V0 而 **V3 也贏 V0**，那增益**不是**「對批次不變」
買來的，只是「中心化」買來的。沒有 V3 就無法歸因。

**為什麼要 V1 與 V2 兩階**：V0 → V2 同時改了兩件事（中心化、尺度），而
**「一次改兩件事然後把效果歸給其中一件」正是這個 session 已經犯過的錯誤形狀**
（C2C-116 的抖動歸因、C2C-120 的粒度假設、C2C-126 的門檻對方向）。

## 二、⚠️ 洩漏界線（三條，都要寫成程式斷言並做變異檢定）

1. **基線只能用 `normal_patrol` 場次。** 良性流量在部署時拿得到；
   **用同批次的全部場次（含攻擊）當基線就是標籤洩漏**，而那會給出一個漂亮而無效的數字。
2. **對 `normal` 場次自己要留一法。** 若一個批次只有少數 normal 場次、而基線把
   被分類的那一場也算進去，它的特徵會變成接近 0 ⇒ **`normal` 的 recall 會
   trivially 衝到 1.0**。所以算 `normal` 場次的基線時**必須排除它自己**。
3. **不得使用 test 列的任何資訊**（含算基線）。工具要斷言 test 列數為 0。

## 四、假設與否證條件

### G1（主要）：批次內正規化要買到東西

Permissive 場次層級 CV：`max(V1, V2) − V0 ≥ +0.05`。

- **否證**：`≤ +0.01`（C2C-067 量到的雜訊地板是 ±0.024，所以 +0.01 以下不可宣稱）。
- 落在 (0.01, 0.05) ⇒ **既未成立也未被否證**（沿用 C2C-123／126 的三分判準）。

### G2（決定性對照）：增益必須真的來自「批次」

`( max(V1,V2) − V0 ) − ( V3 − V0 ) ≥ 0.03`。

- **否證**：`< 0.01` ⇒ **增益不是批次買來的，只是中心化買來的** ⇒ 那麼
  「對良性背景不變」這個框架本身沒有被支持，而 C2C-124 E2 的解讀要重新檢視。

### G3（Enforce 的反向預測，可否證）

Enforce 的增益應該**小於** Permissive 的，而且 **V_best(E) < 0.69**。

- 理由（兩條都是量過的）：整個 18 欄的遙測層在 Enforce 下只值 **0.0009**
  （C2C-121）；而它的單批次幾何 **1.9983** 與 `refresh 640` enforce 的 **1.9234**
  幾乎相同，而後者的實測 CV 是 **0.6851** ⇒ **0.69 是幾何上界**。
- **若 Enforce 超過 0.69，那是一個我沒有預期到的結果**，要在寫結論之前解釋它，
  不可以當成「方法更好」收下。

### G4（洩漏檢查）

`normal` 類別的 recall **不得**跳到 ≥ 0.98。

- 若跳上去 ⇒ 第二節第 2 條的留一法壞了，整輪結果作廢。
- 另一道：**V1／V2／V3 的 `normal` recall 不得明顯高於 V0 的**。

### G5（雜訊地板）

打亂場次標籤（打亂「場次 → 攻擊類別」，而攻擊場次內的 `normal` 列保持 `normal`
—— C2C-064 建立的做法）之後，四個變體都必須落在亂猜附近
（P 亂猜 1/18 ≈ 0.056、E 1/20 = 0.050）。

- **否證**：任一變體的打亂分數 > 0.15 ⇒ 正規化本身洩漏了結構。

## 七、事前已知的限制

1. **CV over train＋validation，不是 holdout ⇒ 即使 G1 成立，百分比也不動。**
   它決定的是「那份新封印值不值得花」，而封印需要**新場次**
   （計劃表 §二：沒有任何未花掉的 holdout）。
2. **批次 id 是 P0 推導的**，而 P0 自己記著：監督器日誌只能當弱佐證
   （可配對的 15／17、不可配對的裡面 5／16 假陽性、涵蓋率約 23%）。
   真正的依據是 gap 雙峰 ＋ 硬邊界。
3. **每批中位只有 13 場**（min 1、max 104）⇒ 小批次的 `normal` 基線很不穩，
   而那會讓 V1／V2 在小批次上噪聲變大。本輪不對批次大小做加權。
4. **`refresh 640` 的 1.0000 本身是單批次上限**（C2C-116）⇒ 它是上界的來源，
   **不是 P1 的目標值**。
5. 單一資料集、`session_aggregate` ＋ `temporal=none`、單一次量測。
