# SROS2 智慧防火牆：即時安全事件接線

日期：2026-08-03  
狀態：程式接線與離線測試完成；live ROS 驗收尚未完成

## 目的

把 ROS 2 節點與 DDS Security middleware 已經做出的安全判斷，轉成可與
PCAP／Zeek 同一時間窗對齊的結構化事件。這條管線只負責觀察與蒐證，不執行
封鎖、不發送測試流量，也不接觸 HMAC secret 或 SROS2 私鑰。

## 資料流

```text
ROS callback / SROS2 log
        │ 固定事件 API（不接受任意欄位）
        ▼
本機 Unix datagram（non-blocking，單筆 ≤4096 bytes）
        │ socket 不存在／壅塞時立即 drop，不拖慢控制迴圈
        ▼
session collector（唯一 JSONL writer）
        │ 驗 schema、來源名稱、數值範圍、sequence
        ▼
telemetry_events.jsonl → session/window 聚合 → fusion_features.csv
```

## 固定事件 schema

所有 datagram 只有六個欄位：`schema_version`、`ts_unix_ns`、
`monotonic_ns`、`source`、`event_type`、`details`。collector 重新指定
`session_id` 與連續 `sequence`，producer 不能自行宣稱 session 或 sequence。

| event_type | details | 來源與意義 |
|---|---|---|
| `hmac_result` | `outcome`, `reason` | 驗章成功或固定拒絕原因；不保存 payload／signature |
| `detector_state` | `detector`, `state` | D1–D6 的 `incident`／`recovery` 狀態轉換 |
| `authenticated_heartbeat_state` | `state`, `gap_sec` | 只以通過 HMAC、channel、timestamp、nonce 的心跳更新 watchdog |
| `graph_state` | `state`, `node_count` | graph query fault、節點數 overflow、recovery |
| `sros2_deny` | `kind`, `count` | authentication、permission、governance deny 類別 |
| `collector_tick` | 無 | 只准 collector 產生，證明該時間窗 collector 在線 |
| `log_reject` | `count` | 只准 collector 產生，記錄 schema／datagram 拒絕數 |

HMAC reason code 固定為：`accepted`、`invalid_configuration`、
`invalid_input`、`malformed_envelope`、`invalid_signature`、
`malformed_body`、`channel_mismatch`、`timestamp_violation`、
`nonce_reuse_or_capacity`。

## 已接線位置

- `intelligent_defense_node`：heartbeat HMAC 結果、D1–D6 incident/recovery、
  D5 authenticated heartbeat gap/recovery。
- `velocity_guard_node`：alert 與 heartbeat 的 HMAC 結果。
- `monitor_node`：graph inspection fault/overflow/recovery。
- `sros2_deny_adapter`：從 middleware log 匯入 deny 類別；原始 log 不進模型資料。
- `orchestrator`：每個 live session 啟動／停止 collector 與 log adapter；缺少
  collector tick 或真實 runtime event 時，該 session 不可訓練。

## 安全邊界

1. producer 使用 `AF_UNIX/SOCK_DGRAM`，不是 TCP/UDP，不會把事件送到其他主機。
2. ROS callback 不等待磁碟或 collector；socket 無法接收時立即返回。
3. 訊息大小、event type、enum、counter、heartbeat gap、graph node count 都有上限。
4. collector output 與 socket parent 不可是 symlink；socket 權限為 `0600`。
5. producer 不能送 `collector_tick`／`log_reject`，也不能加入原始文字或秘密欄位。
6. SROS2 adapter 只保留 deny 類別及計數，不複製憑證、identity、policy 或 token。
7. collector 每秒最多接受 128 筆 runtime event；超量／畸形 datagram 只聚合成
   bounded `log_reject`，不會對每筆垃圾各做一次磁碟寫入。
8. 這條 socket 是蒐證通道，不是封鎖授權。相同 Unix 帳號下的惡意程序仍可能
   嘗試偽造 allowlisted schema；自動回應必須繼續依賴獨立簽章 evidence、網路
   訊號與 response authorizer，不能只相信一筆 telemetry event。

## 還需要 live ROS 驗證

目前不能宣稱「真實即時資料已驗收」。後續必須在使用者允許啟動 ROS 後，完成：

1. 重新 build／source `dds_security_monitor`，重啟 stack，確認三個節點讀到
   `SROS2_FIREWALL_TELEMETRY_SOCKET`。
2. 跑一個不含攻擊的 loopback session，確認每個 network window 都有 tick、
   HMAC accepted 與正常 heartbeat evidence。
3. 使用安全的本機測試 fixture 依序造成 HMAC malformed／channel mismatch／
   timestamp／replay，確認 reason code 與 ROS log 一致。
4. 以受控方式觸發並恢復 D1–D6、heartbeat gap、graph fault／overflow，確認每個
   incident 都恰好有一筆 recovery，且 velocity guard 維持 fail-safe。
5. 用實際安裝的 Fast DDS／Cyclone DDS deny log 校準 adapter；不認得的格式應
   保持 ignored，而不是猜成 deny。
6. 驗證 collector、ROS 節點與測試程序的 Unix 帳號隔離／來源歸屬；在完成前，
   runtime telemetry 不可單獨構成自動封鎖證據。
7. 執行 `--require-multimodal` 品質閘，確認 session/window 無缺漏後，才可把
   `live_multimodal_contract.json` 從 `blocked` 改成通過。

在這七項完成前，模型仍只能 observe／dry-run，不得自動封鎖 IP。
