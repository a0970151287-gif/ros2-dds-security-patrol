## 0. 三句話

1. **序列模型（TCN／GRU）沒有幫助**——兩個模式 × 兩種時序設定 × 兩個網路，**六次比較沒有一次贏過同條件的最佳樹模型**。
   這回答了 C2C-007 從 2026-08-17 開到現在的未決項。
2. **有幫助的是換問題表述**：從「逐視窗分類再池化機率」改成「場次層級聚合再直接
   分類」，Enforce **+0.093**、Permissive 到 **1.0000**。
3. **而換了表述之後，逐視窗的時序特徵幾乎完全多餘**（0.6471 對 0.6505，
   289 場裡差一場）——它本來就是在補舊表述看不見軌跡的缺口。模型因此小 6 倍。

## 2. 宣告的空間（跑之前定死）

| 軸 | 選項 |
|---|---|
| **問題表述** | `per_window_pooled`（現行）／`session_aggregate`／`window_sequence` |
| 模型（前兩種表述） | random_forest／extra_trees／hist_gradient_boosting／**xgboost**／**lightgbm**／mlp／logistic |
| 序列模型 | **tcn**／**gru**（torch，masked pooling、early stopping） |

`session_aggregate` 的統計量（對每個基礎特徵、在一場之內）：

```
mean, std, min, max          ← 全部列（跨 source）
max_abs_delta                ← 相鄰視窗差的絕對值最大，逐 stream、缺口跳過
trend                        ← 該 stream 最後減最初，對 stream 取平均
```

**刻意不放「視窗數」**——那是場次長度，與視窗編號同一類的位置資訊。
有一個測試專門守住這一條（兩場數值相同但長度不同，聚合向量必須一致）。

## 4. 三個讀法

### 4.1 表述的差距比模型的差距大一個量級

Enforce 同一排（固定表述）換模型最多差 **0.055**；換一排差 **0.093**。
而且 `random_forest` 與 `hist_gradient_boosting` 在 `session_aggregate` 上
**同分 0.6505**——兩個不同的模型類別得到相同結果，代表這是表述的功勞，
不是某個模型剛好運氣好。

**XGBoost 與 LightGBM 都沒有贏過 RandomForest**（0.6263／0.6159 對 0.6505）。
MLP 在兩個模式、兩種表述都最差。

### 4.2 為什麼聚合有用

現行做法把每個視窗獨立分類，再平均**機率**；`session_aggregate` 在**特徵層**
合併，保留整場的峰值與變化幅度。

最能說明的是 `parameter_tamper`：**0.059 → 0.765**。參數竄改是一場之中某個時點
的爆量，機率平均會把它稀釋掉，`max` 與 `max_abs_delta` 不會。

⚠️ **不是免費的。** 逐類看是 **7 類改善、2 類退步、8 類不變**：

| 改善 | | 退步 | |
|---|---|---|---|
| `parameter_tamper` | 0.059 → **0.765** | `mission_spoof` | 0.588 → **0.353** |
| `identity_abuse` | 0.471 → **0.941** | `message_dos` | 0.294 → **0.118** |
| `replay` | 0.059 → 0.294 | | |
| `sensor_spoof` | 0.059 → 0.294 | | |
| `health_spoof` | 0.176 → 0.353 | | |
| `discovery_recon` | 0.882 → 1.000 | | |
| `scan_drift` | 0.176 → 0.235 | | |

### 4.3 序列模型：六次比較,零次領先

| | Enforce（有時序） | Enforce（無時序） | Permissive（有時序） | Permissive（無時序） |
|---|---:|---:|---:|---:|
| tcn | 0.5502 | 0.5190 | 0.9725 | 0.9569 |
| gru | 0.5398 | 0.4913 | 0.9804 | 0.9647 |
| 同條件最佳樹模型 | **0.6505** | **0.6471** | **1.0000** | **1.0000** |

**六次比較,序列模型沒有一次贏過同條件的最佳樹模型。**
在 289 場／17 類與 255 場／15 類這個樣本數上，序列模型學不到樹模型學不到的東西。

網路刻意很小（hidden 32、dropout 0.3、early stopping），所以這**不是**「沒調好」；要讓序列模型有機會，需要的是**更多場次**，不是更大的網路。

C2C-007 寫的「輕量 TCN 留到資料與評估契約通過後」——契約現在有了（CV 協定
＋兩道對照），而答案是**這個方向在目前的資料量上不成立**。

## 5. 時序消融：換了表述之後，時序特徵幾乎多餘

| Enforce | `temporal=none`（156 維） | `d1_m3_x3_m5_x5`（936 維） |
|---|---:|---:|
| `per_window_pooled/random_forest` | 0.4083 | **0.5571**（+0.149） |
| **`session_aggregate` 最佳** | **0.6471**（HistGB） | **0.6505**（RF／HistGB） |

**差 0.0034——289 場裡的一場。**

Permissive 同樣的消融：

| Permissive | `temporal=none`（192 維） | `d1_m3_x3` |
|---|---:|---:|
| `per_window_pooled/random_forest` | 0.9725 | **0.9961**（+0.024） |
| **`session_aggregate/random_forest`** | **1.0000** | **1.0000** |

**兩個模式一致**：逐視窗表述需要時序特徵，場次聚合不需要。

這個對比本身就是解釋：逐視窗表述沒有時序特徵就掉 0.149（Enforce）／0.024
（Permissive），而場次聚合完全不在乎。
**那些 `delta1／mean3／max3／mean5／max5` 一直是在補舊表述看不見軌跡的缺口**；
聚合統計量（`max`、`max_abs_delta`、`trend`）本來就是時序摘要，再算一次是重複。

實際效益：**936 維 → 156 維，特徵數從樣本數的 3.2 倍降到 0.54 倍**，
而且整條逐視窗時序管線可以不要。Permissive 是 1,152 維 → 192 維。

（`per_window_pooled/random_forest` 在 `temporal=none` 下是 0.4083，與
2026-09-15 網格量到的 0.4118（2 seed）一致——這一輪的內部參考。）

## 7. 不可宣稱

- **這些是 train ＋ validation 的交叉驗證，不是 held-out test。**
  要變成可引用成績仍然需要一批沒有被花過的 test。**進度百分比不動。**
- **Permissive 的 1.0000 是 255 場全對，樣本數撐不起「錯誤率 0」這種宣稱。**
  支持它不是批次指紋的旁證：C2C-054 在同一批資料上量過 Permissive 消融，
  **network-only 只有 0.2173**——最容易帶批次指紋的那一半很弱。但那是視窗層級
  的舊量測，不是本輪的直接對照。
- **選擇壓力**：16 組在同一批 CV 上比較。表述那一軸的差距（0.093）遠大於組內
  雜訊，但確切數值仍需新 test。
- **出貨模型一個位元都沒改**（`changes_shipped_defaults: false`）。本輪產出的是
  「下次重訓要用什麼設定」的證據。
- **`mission_spoof` 與 `message_dos` 會退步**，換表述前要接受這個取捨。
- 序列模型的結論限於**這個樣本數**。資料多一個量級之後值得重問。
