# 攻擊面那三個缺口：沒有一個是要寫新 runner（2026-10-09）

攻擊面覆蓋停在 **20／23**，而規劃裡一直把它當成「還要寫三支 runner」。
逐個查完之後**沒有一支要寫**——三個缺口是三種不同的東西，而且那道 gate 的
分母來自一個已被宣告 non-deployable 的合成模型。

---

## 一、分母的來源：合成預訓練的類別清單

```

  data_tier = synthetic-pretrain      deployment_eligible = False
  classes n = 23   ← 與 action_policy.json 的 23 條**逐項相同**
```

而 `action_policy.json` 與 `scenarios.json` 是在**同一個 commit**
（`8952f09`，2026-08-06，live multimodal pipeline 的第一個 commit）進來的：

| | 2026-08-06 第一天 | 現在 |
|---|---:|---:|
| `action_policy.json` 規則 | **23** | **23**（從未改變） |
| `scenarios.json` 類別 | **9** | **20**（+11） |

⇒ **`all_policy_classes_present`（`set(classes_) == policy_classes`）從第一個

## 二、逐個缺口，三種完全不同的東西

### `cmd_vel_race` —— 它的 runner 已經在跑，只是被標成別的類別

```
紅隊測試/PoC腳本/N9_cmd_vel_race.py          ← 檔名
  docstring: 「攻擊 N9 — cmd_vel race during emergency stop」
  class CmdVelRacer        def _race()
  log: 「🏁 100Hz publish 0.20 m/s — 跟 patrol pause 競爭 /cmd_vel」
  super().__init__('patrol_node')            ← 偽裝白名單名字

firewall_lab/runners.py:248-251
  if scenario.runner == "cmd_vel_injection":  → N9_cmd_vel_race.py

firewall_lab/scenarios.json
  id=cmd_vel_injection   attack_class=command_injection
  description「未授權高頻 final cmd_vel 注入與控制競爭」
  expected_action: lock_velocity              ← 與 policy 的 cmd_vel_race 逐字相同

firewall_lab/campaign.py:155,175,187,207（四處 hardcode）
  "cmd_vel_injection": ("command_injection", "lock_velocity")
```

而 live 資料裡 `command_injection` 有 **133 場**（enforce 52／合格 42、
permissive 81／合格 75），**它們的攻擊實體全部是 N9 = race**。

兩條 policy 規則的差異只有一個數字：

```
command_injection  action=lock_velocity  adapter=velocity_guard  min_confidence=0.7
cmd_vel_race       action=lock_velocity  adapter=velocity_guard  min_confidence=0.8
```

⇒ **動作層完全相同**（同一個 action、同一個 adapter），只差信心門檻。
C2C-086 記過「多個類別映到同一個動作」，這一對是最極端的例子：
它們映到同一個動作、同一個 adapter，而且**由同一支 PoC 產生**。

### `baseline_poisoning` —— 有 runner，但 gate 判它不可分

候選檔裡有它。兩輪 `lo` 重跑（C2C-062／063）的遙測**逐位等於
「參與者加入」地板**（4 次 alert／1 次 guard_lock），而那個地板是
C2C-062 用一個意外的陰性對照量出來的——`verify_flood` 那一場 rc=2、
一個位元組都沒送，遙測卻完全相同。

⇒ 它通不過證據排他性 gate 不是因為沒有 runner，是因為**它的訊號不帶類別資訊**。

### `node_name_evasion` —— 規避成功，是結果不是缺口

候選檔裡有它。兩輪都是 **0／0／0**，連地板都沒踩到。
機制是它取一個能繞過白名單比對的節點名，所以 monitor 根本沒把它當成未知節點。

⇒ C2C-096 已經記過：要讓它「可產生資料」等於**要讓防禦偵測到它**，那是改防禦。

## 四、不可宣稱

- **百分比不動**：攻擊面覆蓋仍是 20／23（87%）。這一輪改變的是對那個缺口的
  **理解**，不是覆蓋本身。
- 第二節的 `cmd_vel_race` 結論建立在**讀程式**（檔名、docstring、類別名、
  方法名、log 字串、runner 映射、policy 規則比對）——**沒有跑過 N9**，
  所以「它的行為確實是 race 而不是別的」是從程式推的，不是觀測的。
- 兩條規則只差 `min_confidence`（0.7／0.8）是事實；但**那個差異在部署時
  會不會有影響沒有被量過**——`executable_classes` 為空，兩條都到不了執行。
- 第一節的「policy 照合成清單寫」是**類別集合逐項相同**加上**時間順序**
  （08-03 合成 → 08-06 policy）的推論，不是 commit message 的自述。
