## 本輪已完成的防禦

### 1. AI 不能單獨命令防火牆

新增 `firewall_lab/response_authorizer.py`，network response 必須同時具備：

- 模型與 action policy 已驗證且可部署；
- 模型機率分布合法、特徵在允許範圍；
- 來源位於明確授權範圍；
- IP、介面與身份綁定已驗證；
- 來源、介面、DDS 身份、特徵摘要、時間窗、獨立訊號與模型決策必須存在同一個 HMAC 簽章證據 envelope；授權器自行驗章並簽發短效 ticket，禁止拿來源 A 的判斷封鎖來源 B；
- 來源不是 target、allowlist、特殊位址或共享 IP；
- network signal 至少 0.80，另一個獨立訊號至少 0.75；
- attribution confidence 至少 0.95；
- 證據不超過 10 秒，且連續兩個視窗成立；
- backend 是具 kernel timeout 的 bounded set，容量與重啟復原皆驗證；
- TTL 最長 300 秒。

任一條件不成立，只保留告警或 dry-run evidence。

### 2. 模型與政策完整性

- `predict_proba` 每項必須在 0..1 且總和約為 1；異常模型只接受精確 `-1/1`。
- 14 個 network features 加入物理／語意範圍檢查。
- 模型 class 順序、唯一性與 bundle 必須一致。
- action policy SHA-256 綁入已簽章模型 bundle；policy 被改後模型拒絕載入。
- 23 類必須被 policy 完整且精確覆蓋。
- synthetic-pretrain 模型即使判到攻擊，也只能輸出 `alert/none/executable=false`。
- `normal` 永遠只能是 `allow/none`；不合法 action/adapter 配對在載入時拒絕。

### 3. ROS 機器人安全層

- `velocity_guard_node` 開機預設鎖零；在收到新鮮、驗章成功、不可重放的 `/security/heartbeat` 前不放行 controller command。
- heartbeat 超時、D5 fault、generic alert、無 active source、command stale 分成獨立 stop reasons，不會互相誤清除。
- guard 的 alert subscription 改為 `RELIABLE + TRANSIENT_LOCAL`，重啟後可接收最近安全狀態。
- SROS2 policy 已新增 guard 對 `security/heartbeat` 的最小 subscribe 權限。
- D4 的 ROS graph endpoint 查詢發生例外時改為 strong fault，不再 fail-open。
- monitor graph 超過 256 nodes 或無法取得時，只發 bounded aggregate fault、保留舊 baseline 並要求安全停止。
- sensor hub 在 4096 點前先設上限，改用 streaming minimum，避免建立第二份無界 list。

### 4. SROS2 provisioning

- 建立金鑰前固定 `umask 077`。
- canonical least-privilege policy 缺失或是 symlink 時直接停止，不再沿用預設權限。
- canonical policy 仍維持無 wildcard，final `/cmd_vel` 只有 `/velocity_guard_node` 可發布。

### 5. Zeek 與 IP 回應邊界

- Zeek 只負責偵測，不再直接執行 privileged block helper。
- 舊 `DOS_BLOCK_ENABLED` 即使被打開，也只輸出 `response_authorizer_required` 的 suppressed request。
- 原因：單一來源 IP 與流量門檻不足以處理 spoof、NAT、共享 IP 或同 IP 多 participant。
- 舊 iptables + background sleep helper 已改成永遠拒絕的安全樁；安裝器不再安裝 block helper、dos-firewall 或任何 `NOPASSWD` sudoers 規則，服務帳號無法用裸 IP／TTL 繞過授權器。
- 升級路徑也採 fail-closed：安裝器發現舊 helper／sudoers 即拒絕；獨立 revocation 工具只把精確目標移到 root-only 備份，並以 `visudo`、`sudo -n -l` 驗證。列權工具失敗或帳號仍有任何 sudo command 時，不會把它宣告成合格低權限服務帳號。此開發機已唯讀確認沒有舊安裝殘留，未修改系統設定。
- 正式 backend 必須是 nftables/ipset timeout set，且完成容量、併發、expiry、restart reconciliation、audit，以及缺票、換來源、過期、重放與「只採 ticket 來源」測試。回應引擎已固定為只把 5 秒短效 ticket 經 stdin 傳遞，不在命令列或稽核紀錄暴露 ticket；但能跨程序驗票與原子消耗 nonce 的 root backend 尚未實作，所以 live blocking 維持關閉。
- 目前 HMAC `EvidenceVerifier` 是程式介面隔離，不宣稱為密碼學上的 verifier-only 邊界；若要涵蓋回應程序遭入侵的威脅模型，需改成獨立 signer／broker，或使用 Ed25519 等非對稱簽章，讓回應程序不持有簽章能力。
