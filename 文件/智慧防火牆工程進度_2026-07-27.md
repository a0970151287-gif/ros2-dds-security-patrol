## 五、接下來的執行順序

### M0：先保存目前成果

- 將目前尚未凍結的路徑依 source／test／policy／document 分組檢查，排除 runtime、PCAP、秘密、大型資料與 `.codex_tmp/`。
- 排除 PCAP、secret、runtime 與大型產物。
- 建立可回復的 Git commit／tag。

驗收：乾淨 clone 可完成 build、256 項測試及 SROS2 稽核。

### M1：修正正常運行基準

- [已完成 2026-07-28] 修正 `/scan` 前方 ±60° 覆蓋誤判；實際 headless Gazebo readiness 通過。
- Enforce 模式連續巡邏至少 60 分鐘。
- 記錄 CPU、記憶體、封包、警告及必要程序存活。

驗收：零必要程序退出、零異常 scan 忽略、正常巡邏不產生安全告警。

### M2：逐批完成正式資料

- 先跑每情境／模式 5–10 場小批次。
- 每批通過 verifier 後才進下一批。
- 不合格 session 留存證據並 quarantine，不人工改標籤硬塞。
- 完成正常 300、八種受控情境各 100，共 1,100 場。

驗收：1,100/1,100 campaign entry complete；所有 active session 通過 PCAP、Zeek、label、hash、split 與 secret gate。

### M3：訓練正式模型

- 只使用 `training_eligible=true` 資料。
- 以 `session_id` 分組切分。
- synthetic 只做預訓練；最後成績只報 untouched live test。
- 保留 classifier＋normal-only anomaly detector。

建議專題驗收目標（是目標，不是目前成果）：

- 已知攻擊 macro-F1 ≥ 0.75。
- 正常流量 FPR ≤ 2%。
- 重要安全類別 recall ≥ 0.85。
- 未知攻擊 anomaly recall ≥ 0.60。
- 每項指標同時報樣本數與信賴區間。

### M4：驗證防火牆回應

- 先 dry-run 對照預期 action。
- 再逐 adapter opt-in live。
- 驗證封鎖、限流、速度鎖、HMAC 丟棄與 SROS2 拒絕。
- 測試 cooldown、容量上限、解除與故障復原。

驗收：無任意命令執行；錯誤或低信心一律 observe-only；每個 live 動作都有 audit log 與可驗證撤銷。

### M5：建立隔離跨主機驗收場

- 第二台自有攻擊機或 host-only VM。
- 攻擊端與目標端使用不同 IP。
- 無通往校園／公司 LAN 或 Internet 的路由。
- 每次只跑一個授權案例。
- 每案獨立 capture、停止、SHA-256、Zeek 離線分析及報告。

驗收：所有封包目的地均在授權範圍；能清楚分出 prevented、detected、responded、inconclusive，不能補造成功。

### M6：完成報告與展示

- 由 Jesse 從零建立正式主簡報，統一 SROS2、資料集、ML、FPR 及拓樸說法。
- 主簡報只放可重現成果；歷史結果標日期與版本。
- 展示流程準備正常、阻擋、偵測、回應、證據五段。

驗收：老師可從簡報上的每個主要數字追到資料卡、報告、測試或證據檔。

## 六、不能再混寫的證據邊界

- 90,000 合成視窗不是 90,000 筆真實封包攻防結果。
- 合成 PCAP 的 5/5 規則命中不等於真實環境 FPR=0。
- `dry-run` 顯示動作不等於防火牆已實際封鎖。
- SROS2 47/47 靜態稽核不等於所有攻擊都已被 live 擋住。
- 同機 WSL2 測試不能宣稱為真實跨主機網路防火牆證據。
- 20-session pilot 證明資料流程可行，但不能取代 1,100-session 正式資料或生產環境驗證。

## 七、最終判定

目前已完成「防禦架構、主要程式、SROS2 加固、資料管線及小型 live pilot」，所以專題不是從零開始，而是已進入後半段。

真正拖住進度的不是功能數量，而是三件事：

1. 1,100 場正式 live 資料仍未執行。
2. 新模型尚未以足量 live 資料完成可信評估。
3. 隔離跨主機與長時間穩定性驗收尚未完成。

因此目前總進度定為 **68.5%（約 69%）**。完成 M1–M6 並通過定義好的 gate 後，才可標示為 100% 專題完成；即使達到專題 100%，仍不等於未經工業認證的企業生產防火牆。
