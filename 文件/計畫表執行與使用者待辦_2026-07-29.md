## 一、本輪已完成

### 1. 長批次磁碟保護

- `campaign.py` 新增 `--minimum-free-gib`，預設保留 8 GiB。
- 每一個 session 開始前重新檢查，不只在 campaign 啟動前檢查一次。
- 空間不足時，下一個 entry 保持 `pending`，不產生半套 session。
- campaign lock 會正常解除，排除容量問題後可直接續跑。
- 已驗證第一場完成後、第二場空間不足的中斷情境。

### 2. 正式資料版本一致性

- `verify_live_dataset.py` 不再把混合 Git revision 只列為 warning。
- active dataset 若跨越多個 revision，品質 gate 直接失敗。
- revision 為 `unknown` 或不是 40–64 位小寫 Git hex，也直接失敗。

### 3. Zeek SPDP DoS 歸因與記憶體上限

- SPDP burst 與 cooldown 改為 per-source，避免 A 累積 24 包、
  B 發第 25 包時錯怪或錯封 B。
- 所有依來源建立的狀態加入 TTL 與 hard cap。
- 單一來源 timestamp vector 也有上限。
- 容量滿時 fail-closed 拒絕新狀態，並留下 machine-readable metric。
- `DOS_BLOCK_ENABLED` 維持預設關閉。
- 測試 PCAP 全部在本機離線生成，沒有傳送封包。

### 4. 阻止錯誤啟動 1,100 場

計畫主張 14 維 DDS network 加 18 維 ROS／SROS2 telemetry，共 32 維融合；
但複查發現正式 live 管線目前只有 14 維 network，18 維 telemetry 只存在於
synthetic schema。

因此新增 `live_multimodal_contract` preflight gate。未完成下列項目前，
正式 campaign 一律 `BLOCKED`：

1. live telemetry collector；
2. 以 `session_id＋window` 對齊 network 與 telemetry；
3. 產生並驗證 `telemetry_features.csv`；
4. 產生並驗證 `fusion_features.csv`。

這項修正避免收完 1,100 場後，才發現資料無法回答 RQ1／H1
「多模態融合是否有效」。

### 5. 可重現 ML／ROS2 測試環境

- 建立 WSL 原生虛擬環境安裝腳本。
- 建立同時保留專案與 ROS2 Jazzy Python path 的完整測試腳本。
- 原本因 pandas／joblib 缺少而跳過的 7 項測試已全部真正執行。
- 最終結果：`256 passed、0 skipped、0 failed`。

### 6. Source-freeze 衛生

- `.codex_tmp/` 已加入 `.gitignore`，移除 3,605 個本機暫存路徑的干擾。
- runtime、PCAP、模型、大型 pretrain dataset、虛擬環境、SROS2 keystore
  與秘密檔案仍維持不進 Git。
- 尚未建立 commit／tag；既有大量變更屬於使用者專題成果，未經明確同意
  不擅自提交。
