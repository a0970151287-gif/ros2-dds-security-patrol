# SROS2 智慧防火牆：風險登錄與驗收矩陣

更新日期：2026-08-17  
原則：程式存在、單元測試通過、離線證據、同機 live、跨主機 live、真實 kernel 動作與 Raspberry Pi gateway 是不同等級，不互相替代。

## 1. 驗收等級

| 等級 | 定義 | 可以主張 |
|---|---|---|
| L0 設計 | 威脅模型、介面、schema、runbook | 「已設計」 |
| L1 單元／離線 | 純函式、fixture、簽章、重放、路徑、統計測試 | 「離線契約通過」 |
| L2 同機 live | ROS／Gazebo 真實節點，loopback 或同機介面 | 「同機情境通過」 |
| L3 隔離跨主機 | 兩台自有主機、無外部路由、同 revision／seed | 「跨主機情境通過」 |
| L4 真實 kernel／gateway | nftables 真實 rule lifecycle、forward path、重啟復原 | 「gateway response 通過」 |
| L5 Pi 長時間驗收 | Raspberry Pi 5、效能、熱穩定、斷電／網路故障復原 | 「硬體原型可展示」 |

## 2. 核心風險登錄

| ID | 風險 | 影響 | 目前控制 | 現況 | 關閉條件 |
|---|---|---|---|---|---|
| R01 | 模型把正常流量誤判為攻擊 | 合法 ROS 2 通訊中斷 | binary FPR 門檻、family／leaf selective coverage、observe-only | L1 | 新 sealed final holdout 通過，另做事件級 FPR 與 95% CI |
| R02 | 模型高信心猜錯攻擊類別 | 執行錯誤 adapter | binary→family→conditional leaf；未知／低信心只告警 | L1 | 每個可執行 family 的 precision 與 live outcome 達門檻 |
| R03 | 來源 IP 歸因錯誤 | 誤封 gateway／合法節點 | `attribution_verified=false` 時禁止 network action | L1 | 攻擊者 IP、封包、session、label 與 telemetry 直接綁定，network-block precision ≥ 0.98 |
| R04 | SROS2 deny 日誌來源不存在 | 把 source unavailable 誤寫成 0 | availability mask、文件撤回舊 2/2 命中 | L1 | dedicated DDS Security sink 或 direct-delivery canary 提供真 ground truth |
| R05 | SROS2 靜默隔離被誤解為完整防護 | 無法證明訊息未送達 | graph isolation 僅標 proxy；新增 delivery verifier | L1 | Enforce／Permissive 成對 canary，attempt／receipt／health 全綁定 |
| R06 | 資料封存後仍被寫入 | hash 失效、訓練污染 | 外部 exclusion registry；raw 不刪不改 | L1 | 補一筆 corrective session，process-group clean shutdown，重建 frozen release |
| R07 | session／時間窗洩漏 | 指標虛高 | session-grouped split、只用因果歷史、無 future/window index | L1 | 新 paired campaign 加 duplicate／evidence hash overlap gate |
| R08 | SROS2 模式與日期／revision 共線 | 把環境差異誤當 SROS2 效果 | mode separability 揭露；禁止因果宣稱 | L1 | 同 revision、同 scenario／seed、AB/BA 交錯 paired crossover |
| R09 | test 參與過人工調參 | final 成績失真 | 歷史 test 降級 development；新候選 `independent_final_test=false` | L1 | 預註冊新 sealed holdout，只允許一次 final evaluation |
| R10 | nonce 重放或 ticket 偽造 | 重複／未授權動作 | 簽章、原子 nonce、TTL、固定 adapter、policy hash | L1 | 多程序與重啟 live 驗收，clock rollback／duplicate ticket 均 fail-closed |
| R11 | nft rule 未解除或重啟遺留 | 長時間中斷合法服務 | timeout、state DB、recovery 設計；production config disabled | L1 | 真 kernel create→zero→expire→restart→recover 全程證據 |
| R12 | backend 只掛 input chain | 無法成為房間級 gateway | 文件明載 local-input 限制 | L1 | forward／egress 架構、雙網卡、路由與 rollback 驗收 |
| R13 | 本機同主機封包路徑不代表跨主機 | pcap／防火牆結論外推錯誤 | topology 與 claim scope 明列 | L2 部分 | 兩台實體隔離主機、無 default route、第三端確認無越界流量 |
| R14 | Raspberry Pi 資源／溫度不足 | 丟包、延遲、服務退出 | 輕量 sklearn 模型、P95／RSS 待測 | L0/L1 | Pi 5 上 60 分鐘 soak、P95 inference、capture drop、CPU/RAM/temperature 通過 |
| R15 | AI 或回應造成機器人失控 | 人身與設備風險 | velocity guard、急停優先、禁止危險連續輸出、人工覆寫 | L1/L2 部分 | 九項本機 live outcome 與安全故障注入通過 |
| R16 | PCAP／log 洩露校園或辦公室網路資訊 | 隱私與授權風險 | 只在自有隔離網收集；證據不外傳秘密 | L0 | 資料分級、匿名化、保留期限與刪除程序完成 |
| R17 | 金鑰集中化／輪替不足 | 單點洩漏影響多節點 | mode 0600、keystore 不入版控、雙 CA | L1 | 每服務獨立 secret、輪替／撤銷／恢復 live 驗收 |
| R18 | 報告數字與 artifact 不一致 | 嚴格評審失去信任 | evidence ledger、release manifest、禁止覆寫 | L1 | 簡報每一數字對到固定檔案、hash 與生成命令 |

## 3. 九項本機 live outcome 驗收

目前已有 assembler、semantic probe、observer、資料契約與離線測試；尚未產生可當正式結果的 9/9 live pass。

|---:|---|---|---|---|---|

| 2 | Replay／cross-channel | 原子 nonce／channel binding | nonce、reason、sequence | 重放與轉貼拒絕，重啟後仍不重複接受 | 待 L2 |

## 4. SROS2 direct-delivery 驗收

### 4.1 證據三角

```text
attacker attempt sequence
       +
protected receiver receipt sequence
       +
collector heartbeat / clean shutdown
       =
可判定的 delivery outcome
```

只看 publisher stdout 不足以證明訊息送達；只看 receiver 沒收到也不足以證明 SROS2 阻擋，因為 collector 可能故障。因此三者必須綁定相同 session、security mode、policy hash、enclave、topic 與 UTC window。

### 4.2 最小 crossover

| 組別 | 情境 | 模式順序 | seed | 預期 |
|---|---|---|---|---|
| A | unauthorized publisher | Permissive→Enforce | 相同 | Permissive 可送達、Enforce 0 delivery |
| B | unauthorized publisher | Enforce→Permissive | 相同 | 消除順序影響 |
| C | authorized publisher | Permissive／Enforce | 相同 | 兩者都應完整送達，驗證 receiver 健康 |

開發最小 12 場只能證明流程；要報 precision／recall，建議至少 10 對 unauthorized 與 10 對 authorized，共 40 場。

## 5. 房間級自動封鎖部署 Gate

以下任一項不成立，系統只能 observe／alert／dry-run：

- [ ] 新 sealed final test 通過預註冊門檻。
- [ ] `network_block` source-level precision ≥ 0.98、FPR ≤ 0.005。
- [ ] attacker-IP attribution 有獨立 ground truth。
- [ ] protected／management／gateway／loopback source 永不封鎖。
- [ ] 9/9 本機 live outcomes 通過。
- [ ] direct-delivery crossover 通過。
- [ ] nftables 真 kernel timeout、zero、expire、restart recovery 通過。
- [ ] gateway forward／egress path 通過，不只是 local input。
- [ ] 兩台實體隔離主機且無外部路由。
- [ ] Raspberry Pi 5 P95、RSS、溫度、drop 與 60 分鐘 soak 通過。
- [ ] rollback／人工覆寫／evidence export 均通過。

## 6. 停止條件

任何驗收遇到下列情形立即停止，不以「繼續測」掩蓋：

- 目標、來源、網段、時窗或授權欄位不明。
- 封包可能送到非自有或非隔離 IP。
- robot safety guard 不健康或 `/cmd_vel` 可能持續失控。
- capture drop、證據 hash／size 不符、collector heartbeat 缺失。
- 需要讀取／複製私鑰、token、HMAC secret 或 credential。
- 需要 DoS、flood、shell、持久化、提權、credential dumping 或規避偵測。
- 測試會修改帳號、系統安全設定或不可可靠回復的網路狀態。

## 7. 目前結論

目前最成熟的是 L1：資料、模型、安全合約、簽章、重放防護、direct-delivery 驗票器與可重現性工具。L2 有歷史同機平台證據，但九項正式 outcome 未完成；L3–L5 仍需使用者提供隔離雙主機、Raspberry Pi 5 完整硬體與明確 live 授權。這也是為何目前不能宣稱房間級自動封鎖已取得部署資格。
