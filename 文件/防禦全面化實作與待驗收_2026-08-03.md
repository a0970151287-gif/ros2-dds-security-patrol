# SROS2 智慧防火牆：防禦全面化實作與待驗收

日期：2026-08-03  
定位：本文件區分「程式已完成」、「離線證明已完成」與「真實環境尚未驗收」，避免把 mock、合成資料或同機測試誤寫成跨主機成果。

## 一、目前結論

系統已具備完整的防禦資料鏈與預設關閉的暫時封鎖後端，但還不能宣稱可在真實房間網路自動封鎖攻擊者。

目前正確說法是：

> SROS2 與 HMAC 先做預防；D1–D6、heartbeat、ROS graph、SROS2 deny 與網路特徵形成即時證據；模型只提出受限制的防禦意圖；獨立授權器再次驗證來源、信心、雙訊號、連續視窗、保護名單與復原能力；最後才簽發短效 Ed25519 ticket，交給預設停用的 nftables timeout-set 後端。

## 二、已完成的工程項目

### 1. 真實即時資料接線

- HMAC envelope 驗證結果：成功、偽造、重放、跨頻道、過大輸入。
- D1–D6 detector 狀態：事件、解除與恢復。
- authenticated heartbeat：正常、gap 與 recovery。
- ROS graph：fault、overflow 與 recovery。
- SROS2 deny：authentication、permission 與 governance 類別。
- collector 使用連續 sequence、時間新鮮度、大小與速率上限；不完整或失序資料拒絕使用。

這些 telemetry 可以成為模型與證據的一部分，但不能單獨授權封鎖 IP，避免同一程序自行宣稱「我看到攻擊，所以我可以封鎖」。

### 2. 模型工程改善

- 90,000 rows、2,500 sessions、23 classes、32 features。
- train／validation／test 依 session 完全分離，session overlap 為 0。
- validation balanced accuracy：0.9439。
- final test balanced accuracy：0.9392；macro-F1：0.9359。
- test prediction 只執行一次，避免反覆偷看測試集。
- unknown holdout recall：0.7949；anomaly FPR：0.0179。
- 低信心結果降級成 alert，不得直接執行。

重要限制：高分主要來自合成 telemetry；network-only balanced accuracy 約 0.4024。因此模型 artifact 固定標記 `deployment_eligible=false`，不能用來證明真實跨主機自動封鎖能力。

### 3. 防禦動作語意統一

舊版把 network action 寫成 `rate_limit`，但 nftables 規則實際是 drop，報告與行為不一致。現在已統一為：

```text
temporary_block + network_helper + signed TTL
```

- `service_dos`、`spdp_flood`、`node_churn`、`verify_flood` 使用 `temporary_block`。
- 正式 authorizer 與 backend 不接受舊 `rate_limit` ticket。
- 新 1,100-session pending campaign 已重建成新語意。
- 已完成的 20-session pilot 保留舊標籤與原始 catalog hash，只能作歷史證據，不會被改寫；驗證器允許它被驗證，但禁止用舊 catalog 繼續執行新 session。

### 4. 獨立驗票、nonce 與復原後端

- Ed25519 v2 ticket；後端只持有公鑰。
- ticket 綁定 source、evidence、action、adapter、backend、interface、identity 與 TTL。
- SQLite `BEGIN IMMEDIATE` 原子消耗 nonce，重放 ticket 會被拒絕。
- desired state、consumed ticket 與 audit durable 保存。
- 重啟時把 durable state 與 timeout set 重新對帳；過期項目移除。
- active sources 上限 1,024；稽核容量滿時 fail closed，不靜默刪除證據。
- offline simulation 已通過，但明確標記不具 production admission 資格。

### 5. 預設停用的 nftables production 骨架

- 固定 `/usr/sbin/nft`、固定 argv、`shell=False`。
- 只管理專用 `inet sros2_ticket_guard`／`blocked_ipv4` timeout set。
- 只接受簽章 `temporary_block` ticket，不接受 raw IP 或 raw TTL API。
- source 只允許已授權 RFC1918 `/24` 至 `/30`；protected subnet 必須位於授權範圍內且永遠不可封鎖。
- state directory 必須 root-owned `0700`；DB／WAL／SHM 必須 root-owned `0600`；程序要求 `UMask=0077`。
- set 容量 1,024、TTL 最長 300 秒；snapshot／apply／reconcile 後都要重新驗證。
- checked-in config 為 `enabled=false`，source-level live gate 也是 false；mock 或自行填寫 config 都不能開門。

### 6. 跨主機准入 gate

跨主機測試前必須同時通過：

1. signed live multimodal model；
2. 九項本機結果的 raw artifact 語意重算；
3. 真實 production backend acceptance；
4. 兩台不同實體硬體的隔離拓樸證據；
5. SROS2 最小權限與 policy/catalog/action 對齊。

任何一項缺失都輸出 blocked；offline backend report、自填 JSON、同一實體機的 Windows／WSL 或 synthetic model 都不能通過。

## 三、九項本機結果目前狀態

已完成嚴格的 semantic evidence assembler。它不接受操作員直接填 `passed=true` 或任意 facts，而會重開 canonical telemetry、驗 sequence／時間窗／hash／source binding，再逐項重算：

1. normal traffic preserved；
2. unauthorized participant denied；
3. HMAC forgery dropped；
4. replay dropped；
5. oversized input dropped；
6. protected parameter unchanged；
7. velocity guard zeroed；
8. velocity guard recovered；
9. graph failure fail-safe and recovery。

目前是「驗證程式已具備，live pass 尚未產生」。沒有真實 ROS/Gazebo stage artifact 時會直接 blocked，不會補造成功結果。

## 四、尚未完成，不能對外宣稱的項目

- 尚未完成九項本機 live outcome。
- 尚無足量、乾淨標註的 live multimodal 訓練資料；合成模型不可部署。
- 尚未在真實 Linux kernel 驗證 nft timeout expiry、packet drop、容量、GC 與 restart reconciliation。
- bounded live acceptance executor 尚未實作，且需要 root／sudo 與明確人工批准。
- 尚未準備兩台不同實體、完全隔離且沒有 default route／NAT／Internet 的自有主機。
- 目前 nft chain 是單機 `input` 防護，不是房間 gateway 的 `forward/egress`；因此不能宣稱已保護整個房間網路。
- 尚未完成 Raspberry Pi 5 gateway 拓樸、雙網卡、供電、交換器與實體停止程序驗收。
