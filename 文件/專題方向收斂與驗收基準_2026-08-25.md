# 專題方向收斂與驗收基準

決策日期：2026-08-25  
狀態：專題主軸的 canonical 決策；舊報告與舊簡報保留為歷史版本，不刪除。

## 1. 正式題目與名稱規則

### 正式研究題目

> **基於 SROS2 預防與多模態開放集學習之 ROS 2／DDS 入侵偵測與可恢復安全回應**

英文暫定：

> **SROS2-Based Prevention with Multimodal Open-Set Learning for Intrusion Detection and Recoverable Response in ROS 2/DDS**

### 系統名稱

目前一律稱為：**SROS2 智慧防火牆研究原型**。

名稱依證據分三級，不可跳級：

| 等級 | 可用名稱 | 必要證據 |
|---|---|---|
| 目前 | 智慧防火牆**研究原型** | 離線／同機資料、模型、observe-only 回應鏈 |
| 中間 | 智慧入侵偵測與安全回應系統 | AI 研究閘門與 9／9 本機 live outcome 通過 |
| 最終 | 房間級自動封鎖智慧防火牆 | 可信 identity→IP、真 nftables、隔離雙主機、Pi gateway、timeout／重啟復原與 soak 全部通過 |

在最後一級完成前，不得只寫「已建置房間級自動封鎖防火牆」。

## 2. 單一主研究問題

> **在 SROS2 Enforce 已負責身分驗證與最小權限預防的前提下，融合 DDS 網路、機器人行為與安全遙測的多模態 AI，能否對已知與未知攻擊做可靠的偵測或拒判，並且只在攻擊來源可被可信歸因時，觸發可撤銷、可復原的安全回應？**

這個問題把專題收斂成一條完整因果鏈：

```text
SROS2 預防
  -> 可觀測證據
  -> 多模態 AI 偵測／拒判
  -> 可信來源歸因
  -> 短效授權票證
  -> 暫時回應
  -> timeout／解除／重啟復原
```

缺少任一段，就只能報告前一段的研究結果，不能把整條鏈宣稱為完成。

## 3. 三個子問題

### RQ1：AI 是否真的比規則與單一模態有用？

在相同 session-grouped split、相同資料與相同操作點下，比較：

- Zeek／D1–D6 規則基準；
- network-only；
- telemetry-only；
- multimodal fusion；
- 簡單線性／樹模型與分層 open-set 模型。

主張必須來自公平基準、消融與 session-level bootstrap 信賴區間，不能只挑最高單點。

### RQ2：模型能否處理未知攻擊，而不是把未知硬猜成已知？

Permissive 與 Enforce 必須分開報告，並同時呈現：

- binary attack detection；
- known-family／known-leaf classification；
- unknown recall；
- known attack 被誤拒為 unknown 的比例；
- normal false alarm；
- coverage／abstention；
- family-LOO 與完全未參與調整的新 holdout。

原 holdout 的高分不能取代處女 holdout。任何已被反覆診斷或用來選模型的資料，之後只算 development evidence。

### RQ3：AI 的判斷何時有資格觸發防禦動作？

模型輸出本身不直接封鎖 IP。只有下列條件全部成立才可由 observe-only 升級：

1. 模型與資料 release 通過預先登記的 AI 閘門；
2. DDS identity、來源 IP、介面、session 與時間窗有受信任 collector 的獨立 attestation；
3. action policy 明確授權該類別，且 ticket 綁定 nonce、TTL、模型／政策 hash；
4. backend 只接受已驗票 ticket，不接受裸 IP；
5. block、歸零、timeout、unblock、rollback、服務重啟復原都有 live 證據。

低信心、未知來源、證據不足或任何 hash／時間／身份不一致，一律拒絕動作並保留告警。

## 4. 三項研究貢獻

1. **可稽核的 ROS 2／DDS 多模態資料與證據治理。** 以 session 為單位保存 PCAP、Zeek、telemetry、manifest 與 hash，揭露 missing source、重跑、排除與 test 使用歷史。
2. **面向未知攻擊的分層多模態 AI 與失效分析。** 不只報準確率，也研究 SROS2 模式、證據排他性、open-set 誤填、family-LOO 與處女 holdout。
3. **fail-closed、可恢復的 AI 到防禦回應鏈。** 將模型判斷與來源歸因、短效票證、最小授權、timeout、rollback 和重啟復原綁在一起，避免「AI 說封就封」。

## 5. 目前證據能支持的結論

- 1,100 場 campaign 已完成；候選資料使用 1,099 場，300 場缺陷情境已受控重跑並在特徵層替換。
- 二元 attack detection 的封存 test PR-AUC：Permissive 0.9900、Enforce 0.9774。
- 多類 balanced accuracy：Permissive 0.8619、Enforce 0.4155；兩種安全模式不可混寫。
- 修正串流歷史後，原 open-set holdout 的 whole-model recall 為 Permissive 0.5789、Enforce 0.8563；Permissive 的 Mahalanobis 實驗值 0.9543 已反覆使用該 holdout，只能算 development evidence。
- 完全不同的處女 holdout whole-model recall 僅 0.0273；現行資料重算 family-LOO 的四組 acceptance 仍全數未通過。因此「未知攻擊泛化」尚未成立。
- 九項本機 live outcome 目前 5／9；出貨 action policy 的 `executable_classes=[]`。
- 1,101 個 session 中 0 場具備完整 DDS identity→IP attestation；沒有真 kernel nftables、隔離雙主機或 Pi gateway 證據。

因此目前可以主張「研究原型已能建立資料、辨識部分攻擊並安全地拒絕未授權回應」，不能主張「已能在房間網路自動封鎖各種攻擊 IP」。

## 6. 研究驗收閘門

### AI 研究閘門

- 以 session／campaign 分組，train、calibration、selection、test 零重疊；
- 新 final holdout 在所有方法與門檻凍結後只開一次；
- Permissive／Enforce 分開報告；
- 至少有規則、network-only、telemetry-only、fusion 與簡單模型基準；
- 同時報 point estimate、session bootstrap 95% CI、混淆矩陣與 coverage；
- unknown 需至少 family-LOO 加一組真正未參與調整的 holdout；
- normal false alarm、known false-unknown 與 unknown recall 均達預先登記門檻；
- 結果可由固定環境、固定 hash 與單一命令重現。

### 自動回應部署閘門

- 9／9 本機「阻擋、歸零、解除、恢復」有單一 session 完整證據；
- identity→IP 受信任歸因與 publisher authorization context 完整；
- conformal calibration 達有限樣本最低解析度，且與 final holdout 不重疊；
- `executable_classes` 只開放已通過的明確類別；
- 真 nftables 的 block／timeout／unblock／restart recovery／rollback 通過；
- 兩台自有主機置於無外部路由的隔離網；
- Raspberry Pi 5 gateway 完成延遲、CPU、RSS、drop、60 分鐘 soak 與斷電復原；
- 所有 live 動作均有授權範圍、停止條件、PCAP、stdout／stderr、SHA-256 與 observations。

## 7. 明確不做的方向

- 不改成 AI Agent prompt injection／Agent 暴走專題；
- 不把 Metasploit 當作 DDS／SROS2 攻擊的代名詞；
- 不以新增更多攻擊名稱取代資料品質、未知泛化與來源歸因；
- 不把 TQC 自主巡邏、多地圖 RL 或 LLM 模糊測試納入目前核心；
- 不以合成資料、fixture、mock backend 或同機 WSL2 證據替代跨主機／kernel／Pi 驗收。

## 8. 最短關鍵路徑

```text
修正現行 P1/P2 評估輸入與凍結新資料契約
  -> 公平基準、消融、session-bootstrap CI
  -> 新 family-LOO 與處女 holdout
  -> trusted RTPS/DDS identity-to-IP attestation
  -> 9/9 local live outcomes
  -> isolated two-host true nftables acceptance
  -> Raspberry Pi 5 gateway + 60-minute soak
  -> 依證據決定最終題名
```
