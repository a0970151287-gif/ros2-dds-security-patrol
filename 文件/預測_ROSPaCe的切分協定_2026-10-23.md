## 〇、為什麼做這一項

口試最可能被問的一題是：**「文獻都報 0.99，為什麼你們只有 0.4655？」**

這一題有兩個答案，而現在只有一個有證據：

1. **任務不同**：0.4655 是 18／20 類的識別、場次層級、封印 holdout；文獻的
   0.99 多半是二元偵測。這一半已經有證據（我們自己的二元在封印 holdout 上
   是 1.0000／0.9151，C2C-122）。
2. **切分協定不同**：文獻常把逐封包的資料打亂之後隨機切。同一段攻擊裡相鄰的
   封包幾乎一樣，分別落在訓練集與測試集，等於考前看過考題。**這一半沒有證據**
   ——它是一個說法，不是一個量測。

這一項要把第 2 點變成量測，而且是**在別人自己的資料、別人自己的模型上**量，
所以不能被說成「你們的資料比較難」。

## 二、量測（同一個模型、同一組特徵、同一批抽樣列，只換切分）

### 2.1 資料

- **主要輸入**：完整資料集的 CSV，特徵限定為已發表的縮減版的那 60 欄
  （`--feature-columns-from` 縮減版其中一個檔）。理由是作者的筆記本顯示縮減版
  寫出時**已經刪掉 `timestamp`**，而沒有時間就切不出區塊。
- 若下載後發現縮減版檔案其實帶有 `timestamp`，可以直接用縮減版，因為欄位相同。
- **沒有 `timestamp` 的輸入一律拒絕**，**不准退回用檔案順序當時間順序**。

### 2.2 結構的定義

- **run**：相鄰兩列（按時間排序後）相隔超過 `RUN_GAP_SEC` 秒，就開始一個新的 run。
- **sequence**：一個 run 裡同一個標籤的最長連續段。
- **block**：一段 `observe` ＋ 它後面所有的攻擊段，直到下一段 `observe` 或 run 結束。
  run 開頭、前面沒有 `observe` 的攻擊段自成一個 block。
- **block 的種類**：block 裡攻擊標籤的集合；沒有攻擊的是 `observe`。

### 2.3 抽樣（記憶體上限迫使的；WSL 是 9 GB）

- 每個 block 均勻抽最多 `ROWS_PER_BLOCK` 列，比它小的 block 全留。
- 總列數超過 `MAX_ROWS` 時，把每個 block 的上限往下縮到放得下，
  **並把它記成偏離**，不可默默套用。
- 抽樣只用 `SAMPLE_SEED`，**不看任何特徵**。

### 2.4 特徵編碼（不看標籤）

數字照用；`0x…` 轉成整數；其他字串在每一欄裡依 64 位元雜湊的排名編成負整數
（-2、-3、…，不和數字相撞）；缺值 = -1（作者也是 `fillna(-1)`）。

⚠️ 作者用的是 `pd.Categorical` 的字典序編碼，這裡用雜湊排名。兩者都是
**與標籤無關的任意順序**，但**不是同一個順序**——這是已知的差異，記在限制裡。

### 2.5 時間代理（不看標籤，在任何切分之前決定）

一個特徵若在 run 內部隨時間單調變化，就是時間代理：在抽樣列上，對每一個至少有
`PROXY_MIN_ROWS` 列的 run 算 Spearman(特徵, 時間)，取絕對值的中位數，
**≥ `PROXY_RHO` 就算**。

### 2.6 三種切分

| 代號 | 切法 | 對應 |
|---|---|---|
| **row** | 抽樣列逐列打亂，60/40，`random_state` = 每個 seed | 官方範例 A |
| **block** | 每一種 block 各自打亂，60% 進訓練（只有 1 個的種類只進訓練並記錄） | 官方範例 B，加上分層 |
| **chrono** | run 按開始時間排序，最早的幾個 run 累積到 ≥ 60% 列數進訓練，其餘測試；**少於 3 個 run 就不可評估，不退回別的切法** | 本專案的封印 holdout／單批次上限（C2C-116） |

row 與 block 各跑 `SEEDS` 五次；chrono 是決定性的，跑一次。
三種切分都跑兩組特徵：**全部**、**拿掉時間代理**。

### 2.7 模型與指標

- 模型：**作者自己的設定** `XGB_PARAMS`，不調任何東西。
- **主要指標：二元平衡準確率**（攻擊 vs `observe`）。理由：攻擊列佔 78%，
  而平衡準確率不受這個比例影響。
- 次要：PR-AUC（攻擊為正類）、PR-AUC（`observe` 為正類）、
  7 類的平衡準確率（只有 row 與 block）。

## 三、假設與否證條件

一律用 5 個 seed 的**平均**。三分判準沿用 C2C-123／126／127：
落在成立線與否證線之間就是「未定」。

### R1（主要）：按列打亂會把分數灌高

`BA(row) − BA(block) ≥ +0.05`（二元、全部特徵）。

- **否證**：`< +0.01`。
- 我的預測：`BA(row) ≥ 0.97`、`BA(block) ≈ 0.89`，差距約 **+0.08**。

### R2（機制）：灌高的那一段主要來自時間代理

拿掉時間代理之後，R1 的差距至少縮小一半：
`1 − [BA_np(row) − BA_np(block)] / [BA(row) − BA(block)] ≥ 0.50`。

- **否證**：`< 0.10`。
- **不可評估**：沒有偵測到任何時間代理，或 R1 的差距本身 `≤ 0.01`。
- 理由：一個隨時間一路往上加的計數器，讓模型知道「這一列在時間軸的哪裡」；
  逐列打亂時，同一時間點的鄰居就在訓練集裡，標籤可以直接內插出來。

### R3（本專案核心發現在別人資料上的類比）：換一段時間就掉

`BA(block) − BA(chrono) ≥ +0.05`。

- **否證**：`< +0.01`。
- 理由：C2C-116 量到我們自己的資料「每次重啟環境，良性背景就不一樣」；
  如果別人的資料也有這個現象，那 0.4655 不是我們獨有的弱點，而是這一類系統的性質。

### R4（C2C-024 的不對稱）：識別被灌高得比偵測多

用「相對亂猜」正規化之後比較：
`[MC(row) − MC(block)] / (1 − 1/K) ≥ [BA(row) − BA(block)] / 0.5`，
K = 訓練集裡出現的類別數。

- **否證**：不成立（方向相反）。
- **不可評估**：兩個原始差距（二元與多類）都 ≤ 0.01。那時兩邊都只是雜訊，
  「識別被灌得比偵測多」會是空洞為真——C2C-127 的 G4 同一個形狀。
  ⚠️ 這一條是**跑合成負對照時發現的**（兩個差距都約 0，工具卻印出「成立」），
  在提交這份註冊、碰任何真資料之前補上。

## 六、事前已知的限制

1. **抽樣會讓按列打亂的洩漏被低估。** 每個 block 只留最多 5,000 列，時間上相鄰的
   封包變稀疏，「考前看過考題」的程度變小 ⇒ **R1 若成立，它是一個下界。**
2. **縮減版的 60 個特徵，是作者在逐列打亂的訓練集上挑的。** 挑選時看過所有
   block 的列 ⇒ 對 block 與 chrono 稍微有利 ⇒ 對 R1、R3 是**保守**的方向。
3. **標籤是時間窗不是因果**：攻擊時段裡機器人自己的正常封包也被標成攻擊。
   三種切分共用這個缺陷，所以它影響絕對數字，不影響差距。
4. **run 是用時間間隔推出來的**，沒有任何欄位記錄 run 編號——與本專案
   「stack 實例」只能用時間窗代理是同一個限制。
5. **只用作者的一個模型。** 結果說的是**切分協定**，不是我們的模型在別人的資料上
   表現如何（那是 A 項，需要原始 pcap 與 manifest 轉接器）。
6. **粒度不同**：這裡是逐封包，我們是場次層級。**可以比的是「切分協定造成的差距
   有多大」，不是絕對數字**；R1–R4 的任何數字都不可以和 0.4655 直接放在一起。
7. **編碼順序與作者不同**（2.4）。
8. **ROSPaCe 沒有開 SROS2**，所以這一項對 Enforce 什麼都沒說。
9. 單一資料集、單一次量測。

## 七、禁令
