### 實際發生的鏈

```
monitor  🚨 N5 防護：啟動時發現 2 個非白名單節點
monitor  🛑 已要求 velocity guard 鎖零速（signed /security/alerts）
         ↓  跨行程、Enforce 下、HMAC 簽章
guard    ⛔ signed security alert：velocity guard 鎖零速；重複 alert 不延長本次期限
```

三個節點的金鑰指紋一致（`e47dc9c22f70520e`），證明 HMAC 通道真的通了。

`ros2 node list` 的臨時節點 `_ros2cli_10231` 被 SROS2 拒絕（
`rq/_ros2cli_10231/get_type_descriptionRequest topic not found in allow rule`）
——**那是防禦正確運作，不是失敗**。

## 二、兩個環境發現

### `generate_artifacts` 在 sros2 0.13.6 上壞掉

14 個 enclave 全部 `failed to validate namespace: error not set`，但
`create_enclave` ＋ `create_permission` 兩步驟**全部 rc=0**。那不是繞道——
`generate_artifacts` 的文件就說它等於這兩步。

⚠️ **Pi 是 sros2 0.13.6、筆電是 0.13.5**，Fast DDS 也是 2.14.6 對 2.14.5。
兩台機器的 ROS 版本不同，對之後的跨主機測試是要記住的事。

### ⚠️ 第十七次「量測工具偽裝成系統問題」，而這次是我自己

第一次 Enforce 失敗說：

```
Not found topic access rule for topic ros_discovery_info
```

而 `permissions.xml` 裡**明明有那一行**。真正的原因：

```xml
<domains><id>0</id></domains>
```

我產生 permissions 時 SSH session 沒有 `ROS_DOMAIN_ID`（預設 0），執行時卻用
domain 41。**sros2 把產生當下的 domain 寫死進 permissions。**

「規則存在但域不對」與「規則不存在」在 Fast DDS 的錯誤訊息上**完全一樣**。
我一度差點去 policy 裡加一條 `ros_discovery_info` 規則——那會是對著一個不存在
的問題加一條真的放寬。

### 順帶：C2C-041 的陷阱又咬了一次

驗證腳本在 `set -u` **之前**沒有先 source ROS，`setup.bash` 讀未設定的
`AMENT_TRACE_SETUP_FILES` 直接中止。那條紀錄是我自己寫的。

## 三、不可宣稱

- **那個「攻擊」是我自己造成的。** `發現 2 個非白名單節點` 指的是我啟動順序
  不對（monitor 比 guard 晚起）與 `ros2 node list` 留下的 daemon。這**不是**
  一次真實攻擊的偵測，但它是一次**真實的機制驗證**——偵測、簽章、投遞、鎖定
  四段都真的執行了。
- **IDS 的六個偵測器全部 0 命中**（`D1=0 … D6=0`），因為 `odom_hist=0,
  scan_hist=0`——沒有 Gazebo，沒有感測器資料。IDS 起得來、在輪詢，但看不到
  東西。Pi 上跑完整 IDS 要嘛裝 Gazebo（2.1 GB 不夠），要嘛由另一端供資料。
- **沒有任何跨主機場次。** 剩下的是 Pi 防守、筆電攻擊、身份歸因驅動 nftables
  封鎖——那需要兩端，而筆電被 campaign 佔著。
- 節點各跑 12 秒，不是 soak。
