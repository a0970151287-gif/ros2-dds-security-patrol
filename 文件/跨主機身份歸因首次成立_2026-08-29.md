# 跨主機身份歸因首次成立（2026-08-29）

> 這個專題第一次取得 **可信的 DDS identity→IP 歸因**：
> 觀測者在 DDS 認證層記到一筆 `UNAUTHORIZED`，封包層把同一個 GUID 綁到一個來源 IP，
> 兩半交集非零。1,101 場既有資料集裡這個欄位從來都是 `false`。
>
> ⚠️ **仍然不授權自動封鎖**：`authorizes_action=false`。本文只宣稱「歸因成立」，
> 不宣稱「可以自動執行」。

## 一、拿到什麼

session `20260829T191031842634Z_crosshost_76a52ce0`，防守端筆電（WSL mirrored，
`192.168.0.129`）對桌機（`192.168.0.30`）。

**觀測者半邊**（Fast DDS `DomainParticipantListener::onParticipantAuthentication`）：

```
participant_authentication  status=UNAUTHORIZED
guid = a2.5a.10.4e.14.09.85.90.91.80.b1.aa|0.0.1.c1     ×3
```

**封包半邊**（`dumpcap -i eth1 -f udp` → RTPS 解析）：

```
封包看到的 GUID : 2      來源位址 : 2
兩半都看到的 GUID : 1
unique_guid_to_ip_binding            : 2/2
ip_not_shared_by_multiple_identities : 2/2
```

**逐 IP 判定**：

| IP | GUID | 拒絕記錄 | 判定 |
|---|---:|---|---|
| `192.168.0.129`（防守方自己） | 1 | 無 | **不可封鎖** |
| `192.168.0.30`（攻擊者） | 1 | 有 | **可封鎖** |

`source_ip_attribution_verified: true`、`authorizes_action: false`。

## 二、防守方自己的 IP 被正確拒絕，這是同場的陰性對照

`192.168.0.129` 也只掛一個 GUID、也滿足兩個綁定條件，但因為**沒有拒絕記錄**而
判定不可封鎖，理由明寫「不可用查無記錄推論」。

這一點很重要：三條判定不是「唯一 GUID 就封」，而是**必須有觀測者明確的
UNAUTHORIZED 記錄**。C2C-041 加第 3 條就是為了這個——「觀測者靜默失效」是
真實會發生的事，那種情況下每個正常 participant 都會看起來可封鎖。

## 三、握手真的發生了，不是「不在協定裡」

攻擊端回報的封包統計（獨立於防守端）：

| 方向 | 封包 |
|---|---:|
| `.30 → .129` | 131 |
| `.129 → .30` | **87**（前兩輪為 0） |
| IP 分片 | 72，最大 **6196 bytes** |

前兩輪最大只有 876 bytes（純 SPDP 宣告，沒人回應）。6196 bytes 並需要分片，
只有一種東西會產生：**SROS2 握手在交換 X.509 憑證鏈**。

所以這不是 C2C-014 記的那種「無安全設定的 participant 根本不進握手」——
而是**進了協定、出示了憑證、鏈驗不過而被拒**。這正是 Codex 在 C2C-004 第 7 點
要求的東西。

## 四、前三輪為什麼失敗（全部是時序，不是環境）

| 輪次 | 防守端窗 | 攻擊端 participant | 差距 |
|---|---|---|---|
| 1 | 18:07:11–18:08:39 | 未執行 | — |
| 2 | 18:26:43–18:28:40 | 未執行 | — |
| 3 | 18:34:15–18:37:17 | **18:45:00–18:45:40** | **差 7 分 44 秒** |
| 4 | 19:10:37–19:20:37 | **19:15:39–19:16:19** | ✅ 落在窗內 |

第 3 輪的診斷一度往錯的方向走：攻擊端逐包證明 76 個單播 RTPS 離開了網卡，
而防守端一個都沒收到，於是「`.30 → .129` 方向被丟棄」看起來是唯一解釋。
**用擷取檔自己的絕對時間一比就清楚了**——兩個區間零重疊。

根本原因是**兩個代理之間靠人轉述，一來一回好幾分鐘，而窗只開 2–3 分鐘**。
第四輪把窗開到 600 秒就一次成功。

## 五、還不能宣稱什麼

1. **一場、一種攻擊**（N28 wrong-CA）。沒有配對、沒有統計量。
2. **同網段 Wi-Fi**，多播不通（`239.255.0.1` 實測 0/25），靠 unicast initial peer。
   換網路環境要重驗。
3. **沒有整合進特徵**，family-LOO 還沒重做，Enforce 識別與處女 holdout 尚未受益。
4. **`authorizes_action=false`**，仍須經過授權器；`executable_classes` 依舊為空。
5. 1,101 場既有資料集**不會**因此變成有 attestation——那些場次的欄位仍是 0/1,101。
