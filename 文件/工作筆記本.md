## 現在在做什麼

**第一步：Zeek 重建（進行中）**

全部 1,100 場的 Zeek 位元組／封包／duration 資料都是無效的，因為 Zeek 沒有加
`-C`，把 checksum offload 造成的無效校驗和封包全部當成損壞丟棄。

同一份 pcap 實測：

| | 不加 `-C` | 加 `-C` |
|---|---:|---:|
| conn 列數 | 582 | **76** |
| `orig_bytes` | 未設定 | 12840 |
| `orig_pkts` | 0 | 15 |
| `duration` | 未設定 | 40.78 |
| `history` | `CC`（校驗和錯誤） | `D` |

**比拿不到位元組更嚴重的是連線數差 7.6 倍**——`conn_count` 與 `conn_rate` 是
現用特徵，它們一直量到的是校驗和造成的流碎裂，不是連線行為。

可以**完全離線修復**：pcap 都還在，重跑 Zeek 即可，一場 live 都不用重跑。

規則：**不覆寫原始 `zeek/conn.log`**（manifest 有它的雜湊）。重建結果寫到
`zeek_checksum_fixed/`，`features.py` 優先讀它，讀不到才回退。

### 2. 攻擊面擴充

紅隊寫了 **25 個攻擊腳本，資料集只用了 8 個（32%）**。優先加質性不同的：

| 優先 | 攻擊 | 測什麼防禦層 |
|---|---|---|
| 1 | N29 內鬼（有憑證、無 HMAC 金鑰） | **Enforce 下第一個有應用層訊號的攻擊** |
| 2 | N23 白名單名字＋純行為觸發 | 繞過身分檢查，只能靠行為 |
| 3 | N4 跨頻道簽章混淆 | HMAC 頻道綁定 |
| 4 | N21 用 IDS 自己誘發 DoS | 攻擊者借防禦之手（SmartDDoS） |

⚠️ 加入 N29／N30 會**改變威脅模型敘事**（從「純外部攻擊者」變成「也涵蓋憑證
被竊」），論文要重新定義，這是研究設計決定不是工程決定。

### 3. 被動偵察攻擊（目前覆蓋率 0）

八個攻擊**全部會送流量**。純被動的攻擊者只監聽 SPDP／SEDP、繪製拓撲、不送任何
東西，會產生 0 個異常封包，而 14 個網路特徵**全部是速率／比例**，沒有一個看得見
不說話的攻擊者。

這是「小量間接型攻擊」的極端情況，而且它唯一會留下的痕跡是 participant 的存在
本身——也就是身份層，正是 8/31 補起來的那條通道。**這個缺口會讓那條通道的價值
第一次被量到。**

### 4. 來源位址偽造的加固（威脅已寫下的結論）

同網段攻擊者偽造來源 IP 為受害者 → 握手必失敗 → 觀測者記 UNAUTHORIZED →
封包層把 GUID 綁到受害者 IP → **三條判定全過，宣告無辜主機可封鎖**。

8/30 的 79／80 陰性對照測不到（對照組是防守方自己，不是被偽造的第三方）。

鑑別方式已知：真攻擊者有 156 個分片與憑證交換，偽造來源的單向攻擊者握手停在
第一步、不會有憑證流量。判定要加「雙向流量與憑證交換」——**目前沒有檢查**。

**這是滲透測試最該先打的目標。**

### 5. 攻擊參數化

9 個 scenario 只有 2 個真的用到 `intensity`（`oversized_scan`、
`parameter_flood`），其餘 7 個在 `scenarios.json` 宣告了範圍但 runner 忽略。
所以 7 類的 100 場在參數空間裡是同一個點重複 100 次。

⚠️ 做完**識別率很可能下降**——現在的 0.8619 有一部分是「攻擊每次都一樣所以
好認」換來的。那是誠實的下降，但如果目標是分數，這一項是反方向的。

## 不要重犯的錯

| 錯 | 教訓 |
|---|---|
| 觀測者釘傳輸 → 合法節點全被判 UNAUTHORIZED | 同機**不可**釘；跨主機**必須**釘。沒有安全預設值 |
| campaign 不啟動 stack | 它假設 external stack，少了就 `not_eligible:runtime_telemetry` |
| 只重跑受益類別 | 會造出「哪些場次有觀測者」的假象提升。用 `check_channel_coverage.py` 擋 |
| 用平均值比較兩臂 | 一個離群值就能編出不存在的擾動。用中位數 |
| 警告而不阻擋 | 觀測者沒起來只印警告 → 壞資料留在結果裡。要作廢那一對 |
| Zeek 每場都警告校驗和，沒有人讀 | 工具的 stderr 有存進 `zeek_process.json`，但沒有任何檢查看它 |
| 修好資料後表變小就以為修壞了 | 舊表的時間解析度是 bug 的副產物；先問「舊的為什麼會那樣」 |
| 用五元組反轉配對回流 | RTPS 回應來自臨時埠，實測 462 個五元組裡嚴格反轉配對 0 個 |
