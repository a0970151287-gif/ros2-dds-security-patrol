# 資料集來源與產生方法

> 答辯必問：「你的資料哪來的？」
> **一句話答案：不是公開資料集，是我自己在受控環境跑出來的 1,100 場 live 實驗。**

本文所有數字都可以在 repo 內直接核對，每一項都標了出處。

---

## 一、與公開 benchmark 的差別

軸承診斷用 CWRU、網路入侵偵測用 CICIDS2017／UNSW-NB15，這些都是**別人收好的**
公開資料集。本專題**沒有可用的公開資料集**——ROS 2／DDS 層的攻防資料，
公開的要嘛是純封包層、要嘛沒有 SROS2 的 permissive／enforce 對照，
都無法回答本專題的研究問題。

所以資料是自己產生的。代價是規模小、且只有同機環境；
好處是**每一場都有完整的因果紀錄**：誰在什麼時候用什麼種子打了什麼，
防禦端當下記了什麼，全部對得起來。這是公開資料集給不了的。

## 二、產生管線

```
Gazebo + TurtleBot3（受測系統）
   ├─ /scan  /odom  /imu        感測
   └─ /cmd_vel                  巡邏控制
            │
   ROS 2 Jazzy + rmw_fastrtps（DDS domain 30）
            │
   SROS2：permissive 550 場 ／ enforce 550 場
            │
   紅隊腳本（自寫，紅隊測試/PoC腳本/ 共 27 支）
            │
   每場 40 秒攻擊視窗（warmup 5s → attack 40s → cooldown 5s）
            │
   每場同時記錄 18 種 artifact（pcap／Zeek／遙測／各行程 stdout+stderr）
            │
   8 秒視窗切片 → 32 維 fusion 特徵 ／ 14 維 network 特徵
```

執行環境：**Ubuntu 24.04、ROS 2 Jazzy、Python 3.12**，於 WSL2 內同機執行。

## 三、資料組成（`firewall_lab/campaign_1100.json`）

1,100 場 = 300 場 normal ＋ 8 種攻擊情境各 100 場，
permissive／enforce **各 550 場，完全對稱**。

|---|---|---:|---|
| `normal_patrol` | `normal` | 300 | 正常巡邏 |

| `cmd_vel_injection` | `command_injection` | 100 | 速度指令注入 |
| `heartbeat_replay` | `replay` | 100 | 心跳重放 |
| `oversized_scan` | `message_dos` | 100 | 超長 scan 訊息 |

## 四、每一場記錄了什麼

`dataset_live/<session_id>/` 下 18 種 artifact：

| 類型 | 檔案 |
|---|---|
| 原始封包 | `traffic.pcapng` |
| Zeek 分析 | `zeek/conn.log`、`packet_filter.log`、`reporter.log`、`weird.log` |
| 防禦端遙測 | `telemetry_events.jsonl` |
| 標籤 | `labels.jsonl`（逐視窗）、`events.jsonl` |
| 資源用量 | `resources.jsonl` |
| 行程輸出 | 攻擊／擷取／SROS2 adapter／遙測收集器各自的 stdout ＋ stderr |
| 清單 | `manifest.json`（含全部檔案的 size 與 sha256） |

`manifest.json` 記的可追溯欄位：

```
session_id      20260807T080040574491Z_oversized_scan_4942b91b
origin          live_lab
code_revision   339aefd9969aef29292044df8a7d8df7adcda5e9
policy_sha256   897b55777e61709c62d731c775991209edda5ef93f1aed9a808633a3403a37fc
scenario_id     oversized_scan          attack_class   message_dos
security_mode   enforce                 ros_domain_id  30
seed            1326692843              expected_action drop_message
started_utc / ended_utc
randomization   warmup 5s / duration 40s / cooldown 5s / intensity 0.4198
```

**每一場都能用同一個 seed ＋ 同一個 code_revision 重跑**——2026-08-21 的
300 場受控重跑就是這樣做的。

## 五、完整性

全部 **1,101 場、19,204 個 artifact** 做過 size ＋ sha256 全量核對：

- missing_file **0**
- hash 失配 **0**
- size 失配 **1**——`…_ea19b28d/attack.stderr.log`（manifest 3,231 → 磁碟 45,206）

那一場執行於 process-group 終止修正**之前**的 revision `339aefd9`；
修正後的 1,081 場零復發。該場已由 `firewall_lab/dataset_exclusions.v1.json`
釘住排除理由，raw 資料保留不刪。因此正式候選為 **1,099 場**
（Permissive 550、Enforce 549）。

`firewall_lab/features.py` 在 session 被接受進特徵表的當下會重新核對 manifest，
fail-closed；對真實資料實測 **1,100 接受、1 拒絕**，拒絕的正是那一場。

## 六、兩層資料來源，不要混為一談

| 層 | 內容 | 是否用於報告數字 |
|---|---|---|
| `synthetic-pretrain` | 2,500 場／90,000 視窗、22 類攻擊，程式合成 | **否** |
| `live` | 1,100 場 Gazebo live campaign | **是** |

報告引用的兩個模型 `training_metrics.json` 都寫著 `data_tier = live`
（Permissive 550 場／4,397 列，Enforce 549 場／10,777 列）。
合成集走的是 `firewall_lab/train.py` 裡另一條 `synthetic-pretrain` 路徑，
**沒有進入任何一個被引用的結果**。

同一份 `train.py` 的 legacy trainer 已被永久固定為 `deployment_eligible=false`，
避免 `data_tier=live` 繞過正式 gate。

## 七、必須主動講的限制

這些限制講在前面比被問出來好：

1. **同機 loopback，不是跨主機。** 全部在 WSL2 內執行，來源位址只有兩個：
   `127.0.0.1` 與 `10.255.255.254`（WSL 鏡像位址）。
   **因此無法做可信的攻擊者 IP 歸因**——這正是自動封鎖仍為 `blocked` 的原因。
2. **Gazebo 模擬，不是實體機器人。** 沒有 Raspberry Pi 5、沒有第二台主機、
   沒有真實 kernel nftables 驗收。
3. **沒有 RTPS identity attestation。** 1,101 場中 `rtps_identity.jsonl`、
   `identity_attestation.json`、`dds_security_audit.jsonl` 皆為 **0 場**。
4. **300 場重跑是替換不是新增。** 相同 scenario／seed／mode 重跑後在特徵層
   替換，**不可寫成 1,100 + 300 = 1,399 場獨立樣本**。
5. **5 個遙測特徵在真實資料上恆為零或來源不可得**，逐項記於
   `firewall_lab/live_multimodal_contract.json`；不可回填成 true negative。
