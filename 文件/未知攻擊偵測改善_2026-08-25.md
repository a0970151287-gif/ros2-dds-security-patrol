## 〇、更正：評估腳本切斷了串流歷史

### 錯在哪裡

評估腳本先依標籤把要統計的列**過濾**出來，再餵進模型：

```python
holdout_rows = [r for r in rows if r["label"] in holdout_labels]   # ← 錯
```

但 550 場裡有 **393 場同時含 `normal` 與攻擊列**。過濾之後，485/550 條串流
從 `window 1` 開始，該有歷史的列全部拿到 cold-start 特徵——而訓練端
`_expanded_matrix` 用的是**完整 session**。兩邊語意不一致。

`HierarchicalFirewallModel.predict` 本來就會拒絕不連續的 window
（`tests/test_hierarchical_model.py:386` 有守著），但評估腳本用 `reset_stream`
繞過了那道守衛，於是失效是**靜默的**：數字只會偏掉，不會報錯。

順帶更正一句我先前寫錯的話：`evaluate_openset_holdout.py` 的註解說
「693 條串流有 472 條不連續」。對這份 `features_merged_split` 特徵表那是**錯的**
——實測 Permissive 700 條、Enforce 1,647 條串流**全部連續**（window 0 起、
逐一遞增）。那個觀察來自更早的特徵表。

### 修法

整份表逐列依序餵進模型維持歷史，**只在統計時挑要算的列**。並新增
`firewall_lab/stream_replay.py`，把「每條串流恰好 cold start 一次」寫成斷言：
過濾器一旦溜回來就直接拋 `StreamHistoryError`。`tests/test_stream_replay.py`
4 個測試鎖住它，其中一個直接重現當初那個過濾動作。

同時修正 normal 誤判率的分母：舊版用 `novelty_role`（列層級），把 holdout
場次內的 279 個 normal 列也算了進去；holdout 是**整場延後**的 100 場，
所以改成場次層級排除，分母 1,809 → 1,530。

## 一、結論

| 主張 | 證據 | 成立範圍 |
|---|---|---|
| 現行 OOD 頭接近亂猜 | leave-one-class-out macro AUC **0.5381**，六類中四類 < 0.5 | Permissive，訓練列 |
| 換成距離式評分大幅改善 | 整個模型 open-set **0.5789 → 0.9543** | Permissive，原 holdout（**第二次使用**） |
| 在該 validation 操作點沒有代價 | 已知攻擊認對 **0.9158 → 0.9474**、誤否決 0.0596 → 0.0281 | Permissive，validation 平均；family-LOO 最差 fold 有代價 |

open-set recall 的上限仍受**二元閘門對未見類別的 recall**與專屬證據通道限制。

## 二、現行 OOD 頭為什麼接近亂猜

### 2.1 門檻的定法本身就沒有未知參與

`hierarchical_training.py:1176-1192`：IsolationForest 擬合在**所有已知攻擊**的
訓練列上，門檻取那些列分數的 `maximum_known_attack_ood_fpr` 分位數。門檻
**只由已知攻擊長什麼樣決定**。那個 budget 被硬性限制在 `(0, 0.10]`，實測
0.05 → 0.10 只讓門檻從 −0.5581 動到 −0.5296；同時 family／leaf 的 coverage 是
1.000，階層棄權那條路從不觸發。三條通往「未知」的路，實際只有一條在跑。

### 2.2 leave-one-class-out 當模擬未知

對每個已知攻擊類別 c：把偵測器重新擬合在「已知攻擊減去 c」上，用它評 c 的列
（模擬未知）與其餘已知列（已知）。**只用監督訓練列**，holdout 完全不參與。
已知分數一律 out-of-fold（`GroupKFold`，同一場不跨 fold），否則門檻偏低、
未知拒絕率被灌水。

工具：`工具腳本/calibrate_ood_threshold.py`

| 類別 | 模擬未知中位數 | 已知中位數 | AUC |
|---|---:|---:|---:|
| `replay` | −0.5664 | −0.4460 | 0.9726 |
| `parameter_tamper` | −0.5286 | −0.4327 | 0.8937 |
| `replay_dos` | −0.4489 | −0.4598 | 0.4361 |
| `message_dos` | −0.4254 | −0.4604 | 0.3207 |
| `command_injection` | −0.4379 | −0.4560 | 0.3123 |
| `identity_abuse` | −0.4306 | −0.4605 | 0.2934 |
| **macro** | | | **0.5381** |

**六類中有四類 AUC 低於 0.5**——被抽掉時它們看起來**比已知攻擊還正常**。
對這四類，加大 budget 沒有任何用處。

### 2.3 `message_dos` 推翻了「證據排他性」的簡單解釋

`message_dos` 的 closed-set test recall 是 **0.970**（有專屬的
`oversized_message_ratio`），OOD AUC 卻只有 **0.3207**。

瓶頸不是「沒有專屬證據」，而是**評分方式**：IsolationForest 是密度式的，
只有比已知攻擊**更極端**的樣本才會被判成異常。`replay` 與 `parameter_tamper`
被抓到，是因為重跑後它們有極端的特徵值（`parameter_call` 210,614 次）；
`message_dos` 大多數視窗的 `oversized_message_ratio` 是零，落在中央密集區。

**安全上這是最糟的失效方向——安靜的新型攻擊看不見。**

### 2.4 平淡的已知類別會遮蔽平淡的未知類別

把 `command_injection` 與 `identity_abuse` 也移出擬合集之後，同一個
IsolationForest 對 `message_dos` 的 AUC 從 0.3207 跳到 **0.8506**。已知攻擊的
流形只要涵蓋了那塊「平淡」區域，落在同一區的新型攻擊就會被吞掉。
**已知類別越多樣，open-set 越難。**

## 三、換評分器：兩場對抗性驗證

工具：`工具腳本/compare_ood_scorers.py`（用 `_expanded_matrix`，歷史正確，
不受 §0 的更正影響）

三種候選都只需要已知類別的標籤，不需要未知樣本：

- `isolation_forest`：現行做法，密度式。
- `max_softmax`：1 − 已知類別的最大預測機率（OOD 標準基線 MSP）。
- `mahalanobis`：到最近的已知類別中心的馬氏距離，共用組內共變異。

### 3.1 選擇規則先寫下來再跑

**規則：取 LOO 中該候選表現最差的兩類當全新 holdout。** 這兩類完全退出擬合與
LOO 選擇，是最不利於它的情況。兩個候選各做一次。

- 測試 A（針對 mahalanobis 最差的 `identity_abuse`、`command_injection`）
- 測試 B（針對 max_softmax 最差的 `parameter_tamper`、`replay_dos`）

### 3.2 結果

| 評分器 | 測試 A macro AUC | 測試 B macro AUC | **最差情況** |
|---|---:|---:|---:|
| isolation_forest | 0.4316 | 0.6834 | 0.4316 |
| max_softmax | **0.9950** | 0.6900 | 0.6900 |
| **mahalanobis** | 0.8781 | **0.8935** | **0.8781** |

max_softmax 在測試 A 幾乎完美，被針對時從 0.995 崩到 0.690。
**Mahalanobis 是唯一兩場都守住 0.87 以上的。** 安全系統看最差情況。

成本對齊之下（同一個已知誤否決 budget），Mahalanobis 是現行做法的 3–6 倍：

| budget | 測試 A：IF → Maha | 測試 B：IF → Maha |
|---|---|---|
| 0.05 | 0.0195 → **0.3290** | 0.1199 → **0.6972** |
| 0.10 | 0.0391 → **0.4593** | 0.2988 → **0.7337** |
| 0.20 | 0.1401 → **0.8567** | 0.6565 → **0.8699** |

### 3.3 兩種評分器的失效方向互補

- IsolationForest 抓得到**極端**的未知，抓不到平淡的。
- max_softmax 抓得到**模稜兩可**的未知，抓不到極端的——樹模型對訓練範圍外的
  值仍然會自信地分到某一枝（`parameter_tamper` 的 MSP AUC 僅 0.6000）。
- Mahalanobis 對兩者都還可以：距離同時因「極端」與「偏離每個中心」而增加。

合併兩者是合理的後續方向，但那是在看過上表之後才想到的，需要自己的乾淨
驗證，本輪不宣稱。

## 四、接進訓練線

`hierarchical_model.py` 對偵測器只做 duck-typing 檢查（要有 `score_samples`，
且**越低越異常**），所以新增一個包裝類別就能接上，**模型端一行都不用改**。

- 新增 `firewall_lab/ood_scorers.py`：`MahalanobisNoveltyDetector`。
- `hierarchical_training.py` 新增 `--attack-ood-scorer {isolation_forest,mahalanobis}`，
  **預設維持 isolation_forest**，既有 artifact 逐位可重現。
- `tests/test_ood_scorers.py` 9 個測試鎖住方向、奇異共變異、缺標籤、單一類別、
  未擬合、特徵寬度，以及「預設沒有被改掉」。

控制良好：binary／family／leaf 三層的門檻與指標**逐位相同**（threshold
0.3773／0.5664／0.9481、accepted_precision 0.9792），差異完全隔離在 OOD 頭。

**我沒有把預設改成 mahalanobis。** 它在原 holdout 上明顯較好，但在處女 holdout
上兩者都≈0，也就是說優勢是**依 holdout 而定**的；而改預設會讓既有 artifact
不再逐位可重現。要用只需要一個旗標，留給 Jesse 決定。

### 5.2 處女 holdout（`command_injection`、`identity_abuse`）

兩種評分器各訓練一次，其餘設定完全相同。這組 holdout 從未在整個模型層級評估過。

| | IsolationForest | Mahalanobis |
|---|---:|---:|
| 整個模型 open-set recall | 0.0159 | 0.0273 |
| normal 誤判為 unknown | 0.0347 | 0.0365 |
| 被二元閘門判成 normal | 290 / 439 | 290 / 439 |
| 二元閘門 recall（上限） | 0.3394 | 0.3394 |

逐類拆開會看到**同一組 holdout 裡有兩種不同的失效**（Mahalanobis）：

| 類別 | 被閘門漏掉 | 到了 OOD 頭但沒抓到 | 標成未知 |
|---|---:|---:|---:|
| `command_injection` | **221 / 222** | 0 | 1 |
| `identity_abuse` | 69 | 137 | 11 |

`command_injection` 幾乎整類對二元閘門隱形；`identity_abuse` 大多有到達 OOD 頭
（148／217），但頭只標出 11 個。前者要修閘門，後者要修頭——兩件不同的事。

**改善沒有轉移。** 439 列裡有 **290 列（66.1%）被二元閘門判成 `normal`**，
OOD 頭連看都沒看到。工具：`工具腳本/diagnose_openset_paths.py`。

還有一個結構性的不利：**通過二元閘門的列，正是最像已知攻擊的那些列**，
所以它們對 OOD 頭來說也最難。兩個階段互相拉扯。

### 5.3 已知攻擊代價：validation 平均未出現

已知攻擊的 validation 列（n=285）：

| | IsolationForest | Mahalanobis |
|---|---:|---:|
| 誤否決為未知 | 0.0596 | **0.0281** |
| 認對 | 0.9158 | **0.9474** |

宣告的 budget 是 0.05；IF 實現 0.0596（略超）、Mahalanobis 0.0281（低於）。
門檻轉移良好，這與 `calibrate_ood_transfer.py` 的頭層量測一致（IF 0.0613、
Maha 0.0236）。**初版說的「校準得比較差」是錯的，一併撤回。**

#### 5.3.1 但在 family-LOO 的壓力下，代價是真的（2026-08-25 補充）

上表是**出貨門檻在 validation 列上**的表現。改用 Codex 的 leave-one-family-out
協定（每個 fold 移除整個攻擊家族後重新擬合與定門檻，取**最差的 fold**），
結論就不同了。我在**現行**特徵表上重跑四組：

| 設定 | macro unknown recall | worst-fold 已知誤否決 |
|---|---:|---:|
| permissive isolation_forest | 0.0931 | **0.0444** |
| permissive mahalanobis | **0.2709** | 0.2556 |
| enforce isolation_forest | 0.0740 | **0.0833** |
| enforce mahalanobis | **0.1049** | 0.1556 |

Mahalanobis 抓到的未知是 2–3 倍，但**最差 fold 的已知誤否決也高 2–6 倍**。
兩件事都成立，因為量的是不同的統計量：

- §5.3 量的是「候選操作門檻套在 validation 列上的平均」→ 該量測未見代價。
- 這裡量的是「每個 fold 重新定門檻、取最差 fold」→ 有代價。

**所以「沒有代價」只在出貨操作點成立，不可以寫成一般性結論。** 四組在
family-LOO 下都未通過 0.70 的 acceptance（`worst_family_unknown_recall` 為
0.0000–0.0417）。

門檻估計法的比較（`工具腳本/calibrate_ood_transfer.py`，budget 0.05）：

| 估計法 | IF 轉移率 | Maha 轉移率 |
|---|---:|---:|
| `threshold_validation_quantile`（現行，19 場） | 0.0613 | 0.0236 |
| `oof_train_quantile`（314 場 out-of-fold） | 0.0425 | 0.0236 |
| `oof_train_session_weighted` | 0.0708 | 0.0236 |

現行做法只用 19 場估分位數，看起來危險，但實測轉移誤差在可接受範圍內；
Mahalanobis 對估計法完全不敏感。**所以「改用更多場次估門檻」不是當務之急。**

## 六、Enforce：頭層換評分器無效，但整體反而最好

**頭層。** 三種評分器在全新 holdout 上的 macro AUC 分別是 0.3802／0.5867／0.4276，
六類 LOO 也是 0.52–0.55。結果與「SROS2 在 handshake 早期阻斷」的機制一致；但因
vendor deny log 不可得，直接量到的是 0 delivery 與應用層證據不足，而不是 deny 原因；
模型輸入因而主要剩流量形狀。

**但整個模型的 open-set recall 是 0.8563**，比 Permissive 的 0.5789 還高：

| | Enforce（IsolationForest，現行預設） |
|---|---:|
| 整個模型 open-set recall | **0.8563** |
| normal 誤判為 unknown | 0.0170 |
| 二元閘門 recall（上限） | 0.9729 |
| OOD 在可及列的 recall | 0.8801 |

這和頭層的 0.43 不矛盾，但必須講清楚為什麼：**LOO 量的是「平均一個未知類別
有多難」，實際 holdout 量的是「這兩個特定類別有多難」。** `service_dos`
（parameter flood）與 `sensor_spoof` 在流量形狀上都極為顯著，即使只有 network
特徵也認得出「不像已知」；而 LOO 的平均被四個平淡類別拉低。

所以正確的說法不是「Enforce 偵測不了未知」，而是：**Enforce 分得出「有攻擊」
（binary PR-AUC 0.9774）與「沒見過的攻擊」（open-set 0.8563），分不出「是哪一種」
（balanced accuracy 0.4155）。** 三者一起看才是完整的圖像。

## 七、誠實的進度陳述

未知攻擊這一項是**依 holdout 類別而定的區間**，不是單一值：

| holdout | Permissive | Enforce |
|---|---:|---:|
| `sensor_spoof`／`service_dos` | 0.5789（IF）／**0.9543**（Maha） | **0.8563**（IF） |
| `command_injection`／`identity_abuse` | 0.0159（IF）／0.0273（Maha） | 未評估 |

0.70 的門檻在前一組達成、在後一組遠遠未達。**寫報告時不可以只引前者。**
