# 分層 AI：開發期公平基準、特徵消融與效能量測

日期：2026-08-17  
狀態：**development validation only；不是 independent final test，也不是部署或 Raspberry Pi 成績。**

## 1. 評估目的

此評估回答三個開發問題：

1. 因果時序特徵是否比單一目前視窗更有用？
2. 簡單線性／樹模型中，哪一種值得繼續研究？
3. binary、response family 與 leaf subtype 的能力差距在哪裡？

它刻意不自動挑選或發布模型，也不會打開任何 response adapter。

## 2. 防止 test leakage 的契約

`development_evaluation.py` 使用 r2 已釘選的 frozen session contract，並套用目前 v2／r4 的因果時序特徵定義，強制：

- train、selection、calibration、threshold 四組 session 互不重疊。
- novelty holdout 整個 session 不得進 supervised fit、selection、calibration 或 threshold。
- 只檢查 historical test 的 session metadata 以證明排除。
- test label／feature 欄位存取、數值轉換、載入回傳與 prediction 均為 0。
- 所有 fit、selection、calibration、threshold point metric 都使用 session-equal weight。
- 每個結果以 session-cluster percentile bootstrap 估 95% CI。
- output directory 已存在即拒絕覆寫。

輸出固定：

```text
development_only = true
independent_final_test = false
test_not_read = true
test_prediction_passes = 0
deployment_eligible = false
executable = false
```

## 3. 比較矩陣

每個 security mode 比較：

- 3 tasks：binary、family、leaf。
- 5 feature views：current-only、network、telemetry、fusion、causal-temporal。
- 5 models：DummyPrior、balanced Logistic Regression、balanced RandomForest、balanced ExtraTrees、balanced HistGradientBoosting。

因此為 75 組／模式、共 150 組。每組包含：

- macro-F1、balanced accuracy、per-class precision／recall／F1／PR-AUC。
- macro one-vs-rest PR-AUC、ECE、Brier score。
- 200 次 session bootstrap 95% CI。
- fit time、單筆與 batch P50／P95 inference time、observed RSS delta。

## 4. 因果時序最佳候選

排名只使用 selection session；下表的 point estimate 與 CI 來自另一批 threshold development session。

| 模式 | Task | 最佳模型 | Threshold macro-F1 | Session-bootstrap 95% CI | Macro PR-AUC | ECE | Brier | 單筆 P95 |
|---|---|---|---:|---:|---:|---:|---:|---:|
| Permissive | Binary | Logistic Regression | **0.9822** | 0.9560–1.0000 | 0.9917 | 0.0676 | 0.0308 | 0.686 ms |
| Permissive | Family | ExtraTrees | **0.8386** | 0.6741–0.9470 | 0.9230 | 0.1939 | 0.2899 | 2.637 ms |
| Permissive | Leaf | HistGradientBoosting | **0.7478** | 0.6495–0.8223 | 0.8307 | 0.1270 | 0.3460 | 5.447 ms |
| Enforce | Binary | HistGradientBoosting | **0.9708** | 0.9413–0.9948 | 0.9925 | 0.0162 | 0.0251 | 1.555 ms |
| Enforce | Family | RandomForest | **0.6124** | 0.4816–0.7064 | 0.6597 | 0.0864 | 0.5095 | 2.649 ms |
| Enforce | Leaf | ExtraTrees | **0.3803** | 0.2412–0.4547 | 0.4512 | 0.0584 | 0.6987 | 2.742 ms |

Binary 的 Brier 是攻擊機率均方誤差；family／leaf 的 Brier 是多類別機率平方誤差總和，數值定義不同，不應直接跨 task 排名。所有延遲均為目前開發主機量測，不是 Raspberry Pi 5 效能。

## 5. Current-only 與 causal-temporal

依相同 selection ranking 後的 threshold macro-F1：

| 模式 | Task | Current-only | Causal-temporal | 差異 |
|---|---|---:|---:|---:|
| Permissive | Binary | 0.8647 | **0.9822** | +0.1175 |
| Permissive | Family | 0.6803 | **0.8386** | +0.1583 |
| Permissive | Leaf | 0.6969 | **0.7478** | +0.0509 |
| Enforce | Binary | 0.9170 | **0.9708** | +0.0539 |
| Enforce | Family | 0.4482 | **0.6124** | +0.1641 |
| Enforce | Leaf | 0.2225 | **0.3803** | +0.1578 |

這支持「跨視窗脈絡有用」的開發方向，但不能解讀成時序模型已在獨立 final test 顯著勝出。後續仍要在預註冊新資料上用 paired session bootstrap 比較差值 CI。

## 6. 重要負結果

Enforce telemetry-only 的最佳 selection 候選是 Dummy；threshold macro-F1 約 0.3073。這與正式資料中 Enforce telemetry 多數恆零／不可用一致，表示問題是可觀測訊號不足，而不是模型參數不夠。

因此下一步優先：

1. direct-delivery canary 與健康來源。
2. 同 revision paired crossover。
3. 攻擊來源歸因 ground truth。
4. 新 sealed final holdout。

在這些資料補齊前，不應先加入大型 TCN 或 Transformer 來掩蓋訊號缺口。

- 與 hierarchical tests 合併：20 passed。

精確資料稽核：Permissive 的 development validation 為 67 sessions、排除 84 個 novelty holdout sessions；Enforce 為 70 sessions、同樣排除 84 個 novelty holdout sessions。兩者的 historical test label／feature 欄位存取、numeric conversion、載入回傳與 prediction 都是 0。reader 仍會 tokenize mixed-split CSV 的實體列，因此「test_not_read」指的是沒有任何 test semantic field 進入評估，不代表儲存裝置完全沒有讀到那些 bytes。

## 8. 可以與不可以主張的結論

### 可以

- 在 frozen development contract 上，causal-temporal 特徵穩定優於 current-only。
- 二元 normal／attack 很有潛力。
- Permissive family 已有研究價值；Enforce family／leaf 仍不足。
- Enforce telemetry source 缺口是目前的主要瓶頸。

### 不可以

- 不可把 0.9822／0.9708 寫成最終準確率。
- 不可宣稱 test 完全未被歷史研究看過；只能說本 evaluator 沒有使用 test feature／label。
- 不可把開發主機的毫秒數寫成 Raspberry Pi 5 效能。
- 不可用 binary 結果替代 attacker-IP attribution 或 network-block precision。
- 不可因 150 組 evaluation 完成而開啟自動封鎖。
