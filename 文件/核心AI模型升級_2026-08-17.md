# 核心 AI 模型升級：第一階段實作與驗證

日期：2026-08-17  
狀態：離線候選完成；**尚未取得部署、自動封鎖或跨主機資格**

## 1. 這一階段解決了什麼

舊模型把所有攻擊直接做九類平面分類，遇到未知攻擊時仍可能硬猜成某個已知類別；此外，舊 novelty 實驗只讓 IsolationForest 沒看過兩種攻擊，closed-set classifier 其實仍看過，不能稱為完整 open-set 驗證。

本階段新增獨立、fail-closed 的候選管線：

1. Binary head：先判斷 normal／attack。
2. Family head：攻擊成立後，再判斷應對家族（例如 participant deny、control lock、application drop、network block、alert only、quarantine）。
3. Leaf head：只做較細的攻擊類型診斷。
4. Normality OOD：判斷正常流量是否偏離正常分布。
5. Known-attack OOD：判斷攻擊是否偏離已知攻擊分布。
6. Observe-only safety gate：未知、低信心、來源不可用、模式不符或來源歸因未驗證時，一律只告警，不呼叫任何封鎖 adapter。

目前完整決策鏈為：

```text
32 項原始 network + telemetry 特徵
  -> 148 項因果時序特徵與 availability mask
  -> binary normal/attack
  -> attack family
  -> leaf subtype（診斷用途）
  -> normality OOD + known-attack OOD
  -> alert-only candidate decision
```

## 2. 時序特徵與缺失來源處理

時序 key 固定為 `(session/group_id, source)`，只使用目前視窗和最多兩個過去視窗；不使用未來視窗、時間戳或 window index，避免模型偷學固定劇本時序。

每個樣本包含：

- current：32 項
- delta-1：32 項
- rolling mean（最多 3 個視窗）：32 項
- rolling max（最多 3 個視窗）：32 項
- telemetry source availability mask：18 項
- history availability mask：2 項

合計 148 項。

`sros_auth_fail_rate`、`sros_permission_deny_rate`、`parameter_call_rate`、`heartbeat_gap_sec`、`scan_static_ratio` 在目前正式資料中沒有可信 live source，因此標為 unavailable；它們的數值必須為 0，並由 mask=0 明確表示「沒有來源」，不能解讀成「實測為零」。

## 4. Novelty 訓練隔離（未知攻擊效能尚未驗證）

候選模型將 `sensor_spoof` 與 `service_dos` 所屬 session 從以下所有階段排除：

- supervised train
- candidate selection
- calibration
- threshold selection

因此本候選不再沿用「只有 IsolationForest 沒看過 holdout 類別」的做法。這只證明 holdout 類別沒有進入訓練與選模流程，**尚未證明模型能偵測未知攻擊**；兩份候選的 `test_metrics=null`、`test_evaluation_deferred=true`。現有歷史 test 已曾用於人工調整設計，不能再當獨立 final test；本階段也刻意沒有開啟或重算 final test。

解讀：

- 二元「正常／攻擊」結果很有潛力。
- Permissive 的 family head 已達到可繼續研究的程度。
- Enforce 的 family／leaf coverage 非常低；它只在少量高信心樣本作答，不能拿來自動選擇封鎖動作。
- Enforce 的 telemetry 目前幾乎沒有有效變化訊號；增加深度網路或模型參數不能補出不存在的資料。
- Threshold validation 內沒有可評估的 `network_block` family，因此 block-event detection rate 明確為 `not evaluable`；不能用 session-level attack FPR=0 代替封鎖精確率。

## 6. 開發期公平基準與消融（development-only）

為避免只看單一模型分數，另以 `firewall_lab/development_evaluation.py` 執行固定開發期比較。此 evaluator 使用 r2 已凍結的 train／selection／calibration／threshold session contract，並套用目前 v2／r4 的 148 項因果時序特徵定義；它不改寫 r4 artifact，也不會自動選定或發布模型。

比較矩陣為：

- 3 個 task：binary、response family、leaf subtype。
- 5 個 feature view：current-only、network、telemetry、fusion、causal-temporal。
- 5 個模型：DummyPrior、balanced Logistic Regression、balanced RandomForest、balanced ExtraTrees、balanced HistGradientBoosting。
- 每種 SROS2 mode 75 組，共 150 組；每個結果要求 200 次 session-cluster bootstrap。

模型排名只使用 selection session；下表 point estimate 與 CI 來自另一批 threshold development session。數字皆是**開發期結果，不是 independent final test、Raspberry Pi 5 或部署成績**。

## 7. 強制安全邊界

兩個候選 artifact 都固定包含下列 metadata／runtime policy；`deployment_eligible`、`independent_final_test` 與 `test_prediction_passes` 可在 `training_metrics.json` 核對，`executable` 與 `adapter` 可在 signed bundle 與 `MODEL_CARD.md` 核對：

```text
deployment_eligible = false
independent_final_test = false
test_prediction_passes = 0
executable = false
adapter = none
```

此外，legacy `firewall_lab/train.py` 已改為永遠不能寫出 deployment-eligible 模型，避免只因 `data_tier=live` 就繞過正式 gate。

r4／v2 另外加入：

- data／SROS2 policy hash 與 action-policy hash 雙重綁定；任一變更都拒絕載入。
- runtime 自行依 `(session_id, source)` 維護最多兩個過去視窗；跨來源、跨 session、重複、倒退或缺窗不能混入歷史。
- leaf validation 與 runtime 共用同一個 family-conditioned probability helper。
- threshold 必須同時達到 precision、recall、coverage、accepted rows 與 accepted session groups；零覆蓋不再能假裝通過。
- 另報 window、source、session 與 provisional block-event 指標；缺少 network-block ground truth 時回報不可評估。
- 模型、HMAC、metrics、model card、程式 hash、套件版本均由另一份 HMAC-signed release manifest 綁定。

即使模型判斷為 `network_block`，目前資料也沒有可信的 attacker-IP attribution ground truth。telemetry 被複製到多個 source row，不能證明哪個 IP 是攻擊來源；因此本候選不會下發 IP 封鎖。

## 10. 下一階段完成條件

在宣稱核心 AI 可進入 observe-to-dry-run 前，仍需：

1. 收集同一 revision、相同 scenario/seed、AB/BA 交錯的 Enforce／Permissive paired crossover 資料。
2. 隨機化 attack onset、attack-from-start、cooldown 與強度，確認模型沒有偷學固定劇本。
3. 為 Enforce 補 direct delivery canary、可觀測的 telemetry source 與 source-health evidence。
4. 產生獨立 attacker-IP attribution ground truth；沒有歸因就只能 alert。
5. 凍結一批從未用於選模、校準或調 threshold、且包含未見攻擊家族的 sealed final holdout；預先登記 unknown recall、false-unknown rate、coverage 與門檻，只允許一次 final evaluation。
6. 比較 Dummy、Logistic Regression、RandomForest、ExtraTrees、HistGradientBoosting 的同 split baseline；只有時序模型有顯著 CI 優勢時才考慮小型 TCN。
7. 完成九項本機 live outcome、真 kernel timeout／解除／重啟復原，以及兩實體隔離主機驗收後，才可討論自動封鎖。

## 11. 本階段結論

本次已把「模型分數」與「可執行封鎖」正式拆開，也修正 open-set、缺失來源、資料污染和 legacy deployment bypass。核心 AI 從平面九類原型提升為可研究、可追溯、預設拒絕執行的分層候選；但它仍不是房間級自動封鎖防火牆的部署模型。
