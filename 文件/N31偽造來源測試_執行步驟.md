# N31 來源位址偽造測試：執行步驟

> ⚠️ 這份步驟會**產生偽造來源位址的網路流量**，並需要**兩台機器的 root**。
> Jesse 已於 2026-08-31 授權。**由 Jesse 執行**，不由代理代跑。
> 只在你自己的家用網段內做。

## 這是在補什麼

2026-08-31 給封鎖判定加了第四條（鏈路層綁定），擋來源位址偽造。但那條規則
**只有合成資料的單元測試**——`文件/來源位址偽造加固_2026-08-31.md` 明寫著
「沒有實際做過偽造攻擊」。

這份步驟就是去把那句話劃掉。**預期結果是防禦贏**：被偽造的位址判
`spoofing_evidence`、**不可封鎖**。若它反而被判成可封鎖，第四條沒有生效，
那是真實的漏洞。

## 為什麼需要「第三個位址」，以及安全的做法

第四條比的是：

| 方向 | 這個 MAC 是什麼 |
|---|---|
| 收到 `ip.src = X` 的 `eth.src` | 實際發送者 |
| 送往 `ip.dst = X` 的 `eth.dst` | 防守方**自己的 ARP 解析結果** |

所以被偽造的位址 X 必須是防守方**解析得到 MAC** 的。X 若不存在，防守方連
封包都送不出去，測到的會是 `unverifiable`（無法驗證）而不是
`spoofing_evidence`（確證偽造）——兩者都不可封鎖，但只有後者證明檢查真的
認得出偽造。

**建議做法：在防守方加一筆靜態 ARP，指向一個捏造的 MAC。**

- 不需要動到任何真實的第三方裝置，也不會有人收到莫名其妙的封包
- 產生的證據與真實受害者完全一樣：`resolved_macs` 是一個與攻擊者不同的 MAC
- 代價是**要在報告裡揭露**：受害者的 ARP 存在是模擬的，偽造的封包是真的

（若你有一台自己的裝置願意當受害者，也可以直接用它的 IP，那就不必模擬。
代價是它會收到防守方送來的、它不認得的 RTPS 封包——無害，但確實會打擾它。）

## 步驟

### 0. 前置

- 桌機（攻擊機）開機、與筆電同一個網段
- 確認兩邊的 IP：筆電 `192.168.0.129`、桌機 `192.168.0.30`
- 選一個**沒有人在用**的位址當被偽造者，例如 `192.168.0.200`
  （先 `ping 192.168.0.200` 確認沒有回應）

### 1. 筆電（防守方）：加靜態 ARP

```bash
sudo ip neigh replace 192.168.0.200 lladdr 02:00:00:aa:bb:cc dev <你的介面> nud permanent
```

`02:00:00:…` 開頭是本地管理位址，不會與任何真實網卡衝突。介面名用
`ip -br addr` 查（WSL mirrored 下每次開機可能不同）。

確認：

```bash
ip neigh show 192.168.0.200
```

### 2. 筆電：啟動觀測者與擷取

與跨主機批次同一套，只是不啟動攻擊端：

```bash
bash 工具腳本/run_crosshost_identity.sh
```

（它會自己跑 `check_link_layer_binding.py` 並帶進交叉比對。）

### 3. 桌機（攻擊機）：送偽造封包

需要一份含有桌機真實 RTPS 封包的擷取檔當樣板。用先前跨主機場次的即可，
或先跑一次 N28 產生。

```bash
sudo python3 紅隊測試/PoC腳本/N31_source_address_spoof.py \
    --template <某場>/traffic.pcapng \
    --attacker-ip 192.168.0.30 \
    --spoof-ip 192.168.0.200 \
    --target-ip 192.168.0.129 \
    --count 40 --interval 1.0 \
    --i-have-authorization
```

腳本會先檢查樣板酬載裡有沒有內嵌桌機的 IP。**沒有的話會停下來並說原因**：
Fast DDS 回應的是 SPDP 酬載裡宣告的 locator，不是 IP 標頭的來源位址，
所以只改標頭的話防守方會回應到別的地方。

### 4. 筆電：看結果

```bash
cat <本次 session>/link_layer_binding.json
cat <本次 session>/crosscheck.json
```

**通過的樣子**：

```json
"192.168.0.200": {
  "source_macs": ["e8:65:38:20:23:2f"],      // 桌機的 MAC
  "resolved_macs": ["02:00:00:aa:bb:cc"],    // 靜態 ARP 指的 MAC
  "verdict": "spoofing_evidence"
}
```

而 `crosscheck.json` 裡 `192.168.0.200` 的 `blockable` 必須是 `false`，
理由含「來源位址偽造」。

**沒通過的樣子**：`blockable: true`。那就是第四條沒有生效，是真實的漏洞，
要立刻回報。

### 5. 收尾：移除靜態 ARP

```bash
sudo ip neigh del 192.168.0.200 dev <你的介面>
```

**不要忘記這一步。** 留著一筆指向不存在 MAC 的靜態 ARP，之後若有裝置真的
拿到那個 IP，你會連不上它，而症狀會非常難查。

## 三種結果各代表什麼

| 觀測 | 意義 |
|---|---|
| `spoofing_evidence` ＋ 不可封鎖 | ✅ 第四條有效，可以把「只有合成測試」那句劃掉 |
| `unverifiable` ＋ 不可封鎖 | ⚠️ 沒送出流量到被偽造的位址——靜態 ARP 沒生效，或酬載 locator 沒改到。**不算通過**，要查 |
| `blockable: true` | ⛔ 第四條沒生效，真實漏洞 |

第二種要特別小心：它也是「不可封鎖」，看起來像成功，**但它證明的是別的
東西**。這個專案已經被「兩種完全不同的原因產生同一個觀測」咬過六次。
