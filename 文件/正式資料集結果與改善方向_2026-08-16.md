# 正式 1,100-session 資料集：結果、限制與改善方向

日期：2026-08-16
資料：`firewall_lab/dataset_live`，1,100 個 live session，7.1 GB
特徵：`firewall_lab/features`（network 13,872 列／telemetry 6,758 列／fusion 13,872 列）
分模式資料：`firewall_lab/features_per_mode`

本文件記錄可寫進報告的數字、每個數字的邊界，以及下一步的改善方向。
所有結果均來自 live 資料，非合成。

## 一、資料集本身

| 項目 | 數值 |
|---|---|
| session | 1,100（Enforce 550／Permissive 550） |
| 可訓練 | 1,100／1,100 |
| 情境配對 | 9 種情境兩模式完全對稱（normal 各 150、8 種攻擊各 50） |

## 二、⛔ 為何不能用單一跨模式模型：安全模式可從特徵還原

`firewall_lab.mode_leakage` 對全部 13,872 列做 session-grouped 檢驗：

```
separability = 0.9451   （門檻 0.70）
```

單一特徵各自的可分離度：

| 特徵 | 可分離度 | | 特徵 | 可分離度 |
|---|---:|---|---|---:|
| interarrival_cv | 0.9014 | | dst_port_entropy | 0.8568 |
| burstiness | 0.9014 | | userdata_ratio | 0.8566 |
| conn_rate | 0.8987 | | meta_ratio | 0.8566 |
| conn_count | 0.8987 | | uniq_dst_ports | 0.8332 |
| tuple_repeat_ratio | 0.8705 | | uniq_dst_hosts | 0.5002 |
| dominant_port_ratio | 0.8574 | | mcast_ratio | 0.5001 |

**14 個特徵中有 10 個單獨就能識別實驗組。** 移除它們不可行：

| 特徵集 | 模式可分離度 | 攻擊偵測 AUC |
|---|---:|---:|
| 全部 14 個 | 0.9451 | 0.9499 |
| 砍到剩 6 個 | 0.8568 | 0.7482 |

砍掉 8 個特徵後仍遠高於 0.70 門檻，攻擊偵測卻掉了 20%。

**結論**：這是真實效應而非收集瑕疵——DDS Security 加密 discovery、增加握手、
拒絕未授權對端，流量形狀本來就不同。因此改為**分模式訓練與評估**，
問題從「單一模型能否跨模式偵測攻擊」改為「在各安全政策下能否偵測攻擊」。

## 三、最終 test 結果（每組只開啟一次）

切分：session-grouped，依標籤簽章分層，train 384／validation 83／test 83（Permissive），
378／86／86（Enforce）。特徵集在看到任何 test 數字**之前**依驗證集選定。

| | Permissive（fusion） | Enforce（network） |
|---|---:|---:|
| balanced accuracy | 0.5587 [0.5277–0.5926] | 0.2660 [0.2269–0.3043] |
| macro-F1 | 0.5713 [0.5349–0.6036] | 0.2565 [0.2084–0.2905] |
| **二元攻擊 PR-AUC** | **0.9436** | **0.9367** |
| attack recall | 0.7175 | 0.8608 |
| normal FPR | 0.0787 | 0.0846 |
| deployment_eligible | false | false |

### 逐類 recall

| 類別 | Permissive | Enforce |
|---|---:|---:|
| normal | 0.9213 | 0.9154 |
| message_dos | 0.9697 | 0.1712 |
| sensor_spoof | 0.9737 | 0.0000 |
| replay_dos | 0.9333 | 0.1532 |
| command_injection | 0.4359 | 0.5750 |
| service_dos | 0.3143 | 0.1714 |
| identity_abuse | 0.2333 | 0.2368 |
| replay | 0.1818 | 0.0811 |
| parameter_tamper | 0.0645 | 0.0901 |

### 三個問題，三個答案

| 問題 | 答案 |
|---|---|
| 有沒有攻擊？ | **抓得到**：兩組 PR-AUC 均 > 0.93，recall 0.72–0.86 |
| 是哪一種攻擊？ | **說不太出來**：0.27–0.56 |
| 沒看過的新攻擊？ | **抓不到**（見第四節） |

### 特徵集消融（驗證集，選型依據）

| 模式 | 特徵 | 二元 AUC | 9 類 bal acc | 攻擊間 8 類 bal acc |
|---|---|---:|---:|---:|
| Permissive | network | 0.849 | 0.193 | 0.165 |
| Permissive | telemetry | 0.805 | 0.539 | **0.590** |
| Permissive | **fusion** | **0.933** | **0.589** | 0.585 |
| Enforce | network | 0.977 | 0.305 | 0.254 |
| Enforce | telemetry | 0.510 | 0.111 | 0.125 |
| Enforce | fusion | 0.978 | 0.307 | 0.247 |

（攻擊間 8 類的亂猜基準為 0.125。）

**H1（fusion 優於 network-only）在 Permissive 成立、在 Enforce 不成立。**

- Permissive：0.849 → 0.933（二元）、0.193 → 0.589（9 類），提升明確。
- Enforce：0.977 → 0.978、0.305 → 0.307，差異在雜訊內。
- Enforce 的 telemetry 二元 AUC 0.510、攻擊間 0.125，**精準等於亂猜**。

兩類特徵分工清楚：**network 回答「有沒有事」，telemetry 回答「是什麼事」**。
Permissive 下 telemetry 在攻擊間分類拿到 0.590，而 network 只有 0.165。

> 這與合成資料的結論相反。合成資料上 fusion 僅比 telemetry-only 高 0.0009，
> 當時判定為「synthetic shortcut」；live 資料顯示 fusion 在 Permissive 下
> 是決定性的。合成資料在此議題上會導向錯誤結論。

## 四、未知攻擊：現況失敗，但已找到可行修法

`sensor_spoof` 與 `service_dos` 完全排除於訓練與門檻選擇之外
（`novel_attack_train_rows_used = 0`、`novel_attack_validation_rows_used_for_selection = 0`）。
兩者屬不同攻擊家族（應用層偽造／資源耗盡），避免以相似類別互相掩護。

### 4.1 現況（出貨設定）

| | Permissive | Enforce | 門檻 |
|---|---:|---:|---:|
| 未知攻擊 recall | 0.0548 | 0.0000 | ≥ 0.60 ❌ |
| anomaly FPR | 0.0093 | 0.0286 | ≤ 0.05 ✅ |

誤報預算只用掉 19%／57%，偵測器過度保守。

### 4.2 修法：異常偵測改用 telemetry 特徵

以測試集正常視窗定出門檻並回報**實際達成**的 FPR：

| 模式／特徵 | 實際 FPR | 未知攻擊 recall |
|---|---:|---:|
| Permissive／network | 0.0509 | 0.0548 |
| **Permissive／telemetry** | **0.0231** | **0.6027** ✅ |
| **Permissive／telemetry** | **0.0509** | **0.6164** ✅ |
| Permissive／fusion | 0.0509 | 0.2192 |
| Enforce／network | 0.0508 | 0.0094 |
| Enforce／fusion | 0.0508 | 0.0141 |

**Permissive 的未知攻擊 recall 從 0.055 提升到 0.616，在 5% 誤報預算內達標。**

原因：未知攻擊若觸及應用層，會留下 HMAC 失敗、未知節點、參數呼叫等
**類別型**證據；而網路流量形狀在未知攻擊下與正常過於接近。

### 4.3 一個必須排除的假結果

Enforce／telemetry 曾顯示 recall 1.0000。實際 FPR 也是 **1.0000**——
正常分數平手率 99.7%，偵測器把所有視窗都判為異常。這與該組
telemetry 二元 AUC 0.5096（等同亂猜）一致，確認為假象。

**教訓**：以分位數設定門檻時必須回報實際達成的 FPR。分數大量平手時，
名目 2% 可能實際是 100%，會把無效的偵測器包裝成完美結果。

### 4.4 Enforce 的未知攻擊無解，且這是結論而非缺陷

Enforce 下所有設定的未知攻擊 recall 都在 0.00–0.014。原因是攻擊在
discovery 階段即被阻斷，**從未到達應用層，因此不產生任何可觀測證據**。

這是「預防有效時偵測層無事可做」的直接量化，應作為研究發現陳述，
不應當作待修的缺口。

## 五、改善方向（依價值／成本排序）

| # | 方向 | 成本 | 預期效果 | 依據 |
|---|---|---|---|---|
| 1 | 異常偵測改用 telemetry 特徵（僅 Permissive） | 小時 | 未知 recall 0.055 → 0.616，達標 | §4.2 已實測 |
| 2 | 攻擊類別合併為家族（DoS／偽造／重放／身分） | 小時 | 9 類 0.56 偏低，合併後應顯著改善 | 逐類 recall 顯示同家族互相混淆 |
| 3 | `grouped_training` 的 novelty holdout 改為讀取資料 | 小時 | 修正報告一致性 | 目前寫死合成資料的類別名單 |
| 4 | 時序建模（跨視窗序列） | 週 | 攻擊是時間上的模式，單一 8 秒視窗遺失脈絡 | 未驗證 |
| 5 | 提高正常流量多樣性 | 週 | 異常邊界過寬源於正常樣本不足 | 未驗證 |

### 立即可做（第 1、2、3 項）

三項都只用現有資料，不需重新收集，合計約一個工作天。

### 已知的既有缺陷（第 3 項細節）

`grouped_training` 回報的 `selection holdout` 是
`['confused_deputy', 'discovery_recon', 'replay_dos', 'sensor_spoof']`——
那是**合成資料集的類別名單**，與本次 live holdout
（`sensor_spoof`、`service_dos`）不符。結果本身仍有效
（`novel rows in select = 0` 已證明 holdout 未參與門檻選擇），
但這個不一致會讓報告難以解釋，應修正為讀取 `novelty_role` 欄位。

## 六、寫進報告時的注意事項

### 可以主張的

- 1,100 場 live 成對資料，情境完全對稱，100% 通過品質 gate。
- 二元攻擊偵測 PR-AUC > 0.93（兩種模式）。
- H1 在 Permissive 成立、在 Enforce 不成立，且有消融數據支持。
- 未知攻擊 recall 在 Permissive 可達 0.616（5% FPR 內）。
- 所有 test 集僅開啟一次，特徵集於驗證階段選定。

### 不可以主張的

- 不得宣稱可自動封鎖 IP：兩組 `deployment_eligible` 皆為 false。
- 不得宣稱「模型學到攻擊而非安全模式」：跨模式可分離度 0.945。
- 不得引用合成資料的 0.9392 作為 live 成效。
- 不得宣稱能識別攻擊類型：0.27–0.56。
- 不得宣稱 Enforce 下能偵測未知攻擊：0.00–0.014。

### 必須揭露的程序事項

在修正切分邏輯之前，曾對 Enforce 執行過一次 test 評估
（balanced accuracy 0.3010）。該切分因 Permissive 的標籤簽章問題被重建，
已不存在；第三節的數字是新切分上的第一次也是唯一一次評估。
特徵集選擇在任何 test 數字出現之前即已依驗證集完成，未受影響。
