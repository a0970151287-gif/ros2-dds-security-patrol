# SROS2 智慧防火牆：中英文摘要與答辯腳本

更新日期：2026-08-17  
專題題目：**基於網路與機器人行為多模態特徵融合之 SROS2 智慧防火牆與未知攻擊偵測**

## 中文摘要

ROS 2 以 DDS 為通訊中介，具備分散式 discovery、發布／訂閱與即時資料交換能力；然而一般網路防火牆無法同時判斷 DDS participant 是否獲授權、封包是否呈現攻擊模式，以及機器人動作是否符合物理與任務約束。本專題提出一套以 SROS2 為預防核心、結合應用層完整性、行為偵測、網路監測、多模態人工智慧與受限制回應的智慧防火牆原型。

實驗平台以 Gazebo／TurtleBot3 模擬 `/scan`、`/odom`、`/imu` 與 `/cmd_vel` 控制鏈。預防層採用雙 CA、逐 enclave 最小權限與 Enforce；六個 String topic 使用 HMAC envelope v3 綁定 channel、timestamp 與 nonce；D1-D6 偵測超物理速度、方向衝突、雷射重複、非法 publisher、heartbeat 失效及感測／控制不一致；Zeek 與資料收集管線保存 PCAP、事件、telemetry、manifest、版本與 SHA-256。

正式 campaign 完成 1,100 場本機 live session，涵蓋兩種 SROS2 模式與九種情境。完整性重驗發現一場封存後仍持續寫入，故候選模型使用 1,099 場，原始資料保留並透過外部 exclusion registry 排除。特徵由 14 項 DDS network 與 18 項 ROS／SROS2 telemetry 組成，進一步建立 148 維、只使用目前與過去視窗的因果時序特徵與來源可用性遮罩。

核心 AI 採 normal／attack binary head、response-family head、conditional leaf head 與兩個 OOD 路徑。未知攻擊候選從 supervised training、選模、校準與門檻選擇全部排除；歷史 test 已參與過人工設計，因此本輪只回報 session-level development validation，不宣稱獨立 final test。Permissive／Enforce 的 binary balanced accuracy 分別為 0.9793／0.9934；family macro-F1 分別為 0.8522／0.5980。Enforce family coverage 僅 0.1333，且資料沒有可信 attacker-IP attribution，因此候選固定 observe-only，不能自動封鎖。

本專題的主要貢獻為：(1) 可追溯的 ROS 2／DDS 多模態資料工廠；(2) 將缺少來源與實測為零明確分開；(3) 避免 session 洩漏與未知攻擊訓練污染的評估契約；(4) 以簽章、nonce、TTL、cooldown、白名單與復原機制隔離 AI 判斷和系統動作；(5) 對未完成的 direct delivery、kernel nftables、隔離跨主機與 Raspberry Pi gateway 驗收維持 fail-closed。結果顯示，二元攻擊偵測具有潛力，但安全模式混淆、來源歸因與實機回應仍是部署前的主要研究問題。

關鍵詞：ROS 2、DDS Security、SROS2、智慧防火牆、多模態學習、未知攻擊、機器人資安、可重現實驗

## English Abstract

ROS 2 relies on DDS for distributed discovery and real-time publish-subscribe communication. A conventional perimeter firewall, however, cannot jointly determine whether a DDS participant is authorized, whether network traffic exhibits an attack pattern, and whether robot behavior remains consistent with physical and mission constraints. This project presents a defense-in-depth SROS2 intelligent-firewall prototype that combines preventive access control, application-layer integrity, behavioral detection, network monitoring, multimodal machine learning, and constrained response.

The experimental platform uses Gazebo and TurtleBot3 to simulate the `/scan`, `/odom`, `/imu`, and `/cmd_vel` chain. SROS2 Enforce, separate identity and permission CAs, and least-privilege enclaves form the primary prevention layer. HMAC envelope v3 binds channel, timestamp, and nonce on six String topics. D1-D6 detectors monitor implausible velocity, directional conflict, repeated laser scans, unauthorized publishers, heartbeat loss, and sensing-control inconsistency. Zeek and the data pipeline preserve PCAP, events, telemetry, manifests, software revision, and SHA-256 evidence.

The formal campaign completed 1,100 local live sessions across two SROS2 modes and nine scenarios. Integrity re-verification found one artifact that continued growing after its manifest was sealed; the candidate release therefore uses 1,099 sessions while preserving the raw session and recording the exclusion externally. Fourteen DDS-network features and eighteen ROS/SROS2 telemetry features are transformed into 148 causal temporal features using only current and past windows with explicit source-availability masks.

The AI pipeline consists of a normal-versus-attack binary head, a response-family head, a family-conditioned diagnostic leaf head, and two out-of-distribution paths. Novel attack candidates are excluded from supervised training, selection, calibration, and threshold tuning. Because a historical test set influenced earlier design choices, the current release reports development validation only and does not claim an independent final test. Binary balanced accuracy is 0.9793 in Permissive mode and 0.9934 in Enforce mode; response-family macro-F1 is 0.8522 and 0.5980, respectively. Enforce family coverage is only 0.1333, and the dataset lacks trusted attacker-IP attribution. Consequently, every candidate decision remains observe-only and non-executable.

The contributions are: (1) a traceable multimodal ROS 2/DDS data factory; (2) explicit separation of unavailable evidence from measured zero; (3) session-safe and novelty-safe evaluation contracts; (4) a signed, nonce-protected, time-bounded, allowlisted, and recoverable separation between AI inference and system action; and (5) fail-closed handling of unfinished direct-delivery, kernel nftables, isolated cross-host, and Raspberry Pi gateway acceptance. The results show strong potential for binary detection, while mode confounding, source attribution, and real-device response remain the principal deployment barriers.

Keywords: ROS 2, DDS Security, SROS2, intelligent firewall, multimodal learning, unknown attacks, robot cybersecurity, reproducible experimentation

## 30 秒版本

> 一般防火牆只看 IP 和 port，但 ROS 2 攻擊還牽涉 DDS 身分、topic 權限和機器人的物理行為。我做的系統以 SROS2 先阻止未授權 participant，再用 HMAC、D1-D6、Zeek 與多模態 AI 看跨層異常。正式資料收了 1,100 場，本輪以完整性有效的 1,099 場建立分層模型；二元偵測在 development validation 很強，但目前沒有可信攻擊來源 IP，也還沒做 Pi gateway 和 kernel 封鎖驗收，所以系統刻意維持只告警，不誇大成可部署。

## 3 分鐘版本

### 0:00–0:30 問題

一般防火牆不知道 ROS 2 的節點身分、topic 權限，也不知道 `/cmd_vel` 是否會讓機器人失控。因此我們把問題拆成三層：誰能加入 DDS graph、網路是否有攻擊模式、機器人行為是否合理。

### 0:30–1:10 系統

SROS2 Enforce 與最小權限是第一層預防；HMAC v3 防偽造、重放與跨頻道轉貼；D1-D6 和 velocity guard 檢查機器人行為；Zeek 觀察 DDS／網路事件；AI 融合 14 個 network 與 18 個 telemetry feature。最後的回應引擎不是看到異常就封鎖，而是要通過信心、白名單、cooldown、容量、ticket、nonce、TTL 與復原閘門。

### 1:10–2:05 資料與 AI

正式 campaign 完成 1,100 場、兩種 SROS2 模式與九種情境。完整性稽核找出一個封存後仍變動的 session，所以模型只使用 1,099 場，沒有修改原始資料。新模型先判 normal／attack，再判應對 family，leaf 只作診斷，另外有 unknown／OOD 路徑。時序特徵只看現在和過去，缺少 SROS2 日誌來源會用 mask 表示，不拿 0 假裝實測。

### 2:05–2:35 結果

目前是 validation-only。Permissive 與 Enforce binary balanced accuracy 為 0.9793 與 0.9934；family macro-F1 為 0.8522 與 0.5980。Enforce family coverage 只有 13.33%，說明預防層改變了可觀測資料，不能只靠更大的模型解決。

### 2:35–3:00 邊界與貢獻

現階段沒有 attacker-IP ground truth，也沒有兩台隔離主機、Pi gateway 與真實 nftables 驗收，因此絕不宣稱能自動封鎖。專題真正的貢獻是把 ROS 2 安全、資料品質、AI 評估與安全回應做成可追溯、可撤銷、可重現的工程鏈。

## 常見追問與回答

### Q1：這不就是規則式 IDS，AI 新意在哪裡？

規則層負責可解釋且必須立即阻止的已知危險；AI 研究的是 network 與 robot telemetry 的跨層組合、時間脈絡、拒絕作答與未知攻擊。新模型不是直接九類硬猜，而是 binary、response family、conditional leaf 與 OOD 分層，且每一層都可被單獨消融。

### Q2：為什麼不用深度學習？

目前資料的主要限制是 Enforce telemetry 訊號不足，不是模型容量不足。先用 Logistic Regression、RandomForest、ExtraTrees 等可重現基準建立證據；只有因果時序模型在同 split、session-bootstrap CI 下顯著勝出，才有理由加入小型 TCN。這比為了「看起來像 AI」而增加參數更科學。

### Q3：1,100 場為什麼模型只用 1,099 場？

其中一場的 `attack.stderr.log` 在 manifest 封存後繼續寫入，bytes 與 SHA-256 不再一致。我們不修改原始檔或補造 hash，而是用外部 exclusion registry 釘住預期／實際值並從訓練排除。這是資料治理成果，不是失敗。

### Q4：0.99 的 binary 結果是不是過擬合？

它是 development validation，不是 final test，也不能直接等於部署表現。兩種模式在日期、revision 與 seed 上仍有混淆，mode separability 曾達 0.9451；所以後續必須做同 revision、相同 scenario／seed、AB/BA 交錯的 paired crossover，並收新的 sealed final holdout。

### Q5：SROS2 deny 為什麼是 0？

不能解讀成實測沒有拒絕。現行 Fast DDS 沒有配置可信的 security audit sink，一般 stdout 也不是可驗證來源，因此兩個 deny feature 被標為 `source_unavailable`。目前只能用 graph isolation proxy；下一步用有 attempt sequence、receipt sequence 與 heartbeat health 的 direct-delivery canary 直接證明是否送達。

### Q6：現在能不能自動封鎖 IP？

不能。模型沒有可信 attacker-IP attribution，backend 的 production gate 關閉，而且尚未完成真實 kernel、timeout、解除、重啟復原、兩台隔離主機與 Pi gateway 驗收。現在的正確狀態是 alert／observe-only。

### Q7：那為什麼叫防火牆？

因為目標產品是「以 SROS2 為核心、能對 DDS／ROS 2 身分、資料、行為和網路來源做政策判斷的 room-level gateway」。目前完成的是可驗證的防火牆研究原型；名稱描述目標架構，簡報會清楚分開 prototype 與 deployment-ready。

### Q8：Metasploit 能不能證明 DDS 安全？

Metasploit 適合主機服務暴露與已知模組檢查，不等於 DDS／SROS2 測試。DDS discovery、publish／subscribe、parameter 與 permission 必須標記實際 ROS 2／DDS 工具與協定。任何測試只在自有、隔離、無外部路由環境進行。

### Q9：社會價值是什麼？

機器人資安不只是資料保密，也關係到人身安全與服務可用性。本專題強制低信心只告警、急停優先、可撤銷、保護來源與人工介入，並把未完成的證據標為 blocked，降低 AI 誤動作與研究過度宣稱帶來的風險。

- 「我們已經可以在房間網路自動封鎖任何攻擊 IP。」
- 「1,100 份資料全部通過目前的完整性驗證。」
- 「0.99 就是最終準確率。」
- 「SROS2 deny 為 0，所以沒有任何攻擊。」
