## 三、必須回答的 AI 研究問題

### RQ1：多模態融合是否真的有用？

> DDS 網路特徵與 ROS2／SROS2／HMAC 行為特徵融合後，是否比 network-only、telemetry-only 與 Zeek 規則式取得更好的 macro-F1、重要攻擊 recall 與 FPR？

### RQ2：能否偵測訓練時沒看過的攻擊？

> 將一種或多種攻擊類別完全排除於訓練後，normal-only anomaly detector 或融合模型能否在 untouched live test 中辨識未知攻擊？

### RQ3：SROS2 模式如何改變可觀測資料？

> 相同情境在 Permissive 與 Enforce 下的封包、認證失敗、權限拒絕及 ROS 行為特徵有何差異？模型是否只是記住安全模式，還是真的學到攻擊行為？

### RQ4：AI 回應是否安全且即時？

> 在信心門檻、cooldown 與容量限制下，系統是否能降低誤封，同時在可接受時間內完成告警、限流或速度鎖定？

## 四、待驗證的研究假設

- **H1**：fusion 模型的 macro-F1 高於 network-only 與 telemetry-only。
- **H2**：session-grouped split 的結果低於逐列隨機切分，但更接近真實泛化能力。
- **H3**：加入 normal-only anomaly detector 能提升未知攻擊 recall。
- **H4**：SROS2 Enforce 可顯著降低成功攻擊流量，但也會改變可見特徵分布。
- **H5**：安全回應閘門可降低誤封，且不會讓 P95 端到端反應時間失控。

若實驗不支持假設，也必須誠實報告；AI 專題的價值在可重現研究結果，不是每個假設都要成功。

## 五、模型與比較實驗設計

### A. 規則與傳統基準

1. Zeek 五類固定規則。
2. Logistic Regression 或線性分類器。
3. RandomForest。
4. Gradient-boosted tree（使用目前環境可穩定重現的實作）。
5. Normal-only IsolationForest。

### B. 神經網路基準

- 32 維 fusion features 的 MLP。
- 若保留連續多個 8 秒視窗，可加入 1D temporal encoder 作為序列基準。

### C. 建議核心模型

建立雙分支融合架構：

```text
14 維 DDS network features ── network encoder ──┐
                                                ├─ fusion layer ─ classifier head
18 維 ROS/SROS2 telemetry ─ telemetry encoder ──┘              └ anomaly score
```

最低要求：

- 兩個分支可獨立移除，才能做消融。
- classifier 與 anomaly score 必須能分開評估。
- 模型選擇只能使用 train／validation，untouched test 只開一次做最終報告。
- 若雙分支模型沒有顯著優於簡單 RF，必須誠實以「資料與特徵研究成果」定位，不得硬宣稱深度模型較強。

## 六、正式資料規則

- 正式目標：1,100 live sessions。
- 正常巡邏：300 sessions。
- 八種受控攻擊情境：各 100 sessions，共 800。
- Permissive／Enforce：各 550。
- 每個 session 必須有獨立 seed、manifest、label、PCAP、Zeek、policy hash 與 evidence hash。
- split 單位只能是 `session_id`，相鄰視窗不得跨 train／validation／test。
- 90,000 synthetic windows 只能用於預訓練及管線開發。
- 最終準確率只能使用未參與選模的 live test。
- 失敗、丟包、空 PCAP、標籤錯位或證據不完整的 session 必須 quarantine。
- 建議保留至少一個完整情境作 unknown-attack holdout。

## 七、AI 系必做實驗

| 實驗 | 比較內容 | 主要輸出 | 完成條件 |
|---|---|---|---|
| E0 資料品質 | active vs quarantine、split、duplicate、finite、class balance | dataset card、品質報告 | 所有 gate 通過且人工抽查一致 |
| E1 基準模型 | Zeek、線性模型、RF、boosted tree、MLP、IsolationForest | 統一 test metrics | 使用完全相同的 session split |
| E2 特徵消融 | network-only、telemetry-only、fusion | macro-F1、FPR、每類 recall | 能量化融合帶來或沒有帶來的改善 |
| E3 模型消融 | 移除單一分支、anomaly head、confidence gate | 指標與延遲變化 | 每個模組的作用可被獨立解釋 |
| E4 未知攻擊 | leave-one-class-out／多類 holdout | unknown recall、AUROC／AUPRC | 訓練資料完全不含 holdout 類別 |
| E5 SROS2 對照 | 相同情境 Permissive vs Enforce | 攻擊成功、拒絕、特徵分布 | 配對 session 與相同 seed／強度 |
| E6 安全回應 | observe-only、dry-run、live adapter | 誤封、動作成功率、P95 延遲 | 可撤銷、可稽核、低信心不出手 |
| E7 統計穩定性 | 多 seed 或 grouped folds | mean、std、95% CI | 不以單次最高結果當結論 |

## 八、建議驗收門檻

以下是建議專題門檻，不是目前成績：

- 已知攻擊 macro-F1 ≥ 0.75。
- 重要安全類別 recall ≥ 0.85。
- 正常流量 FPR ≤ 2%。
- 未知攻擊 anomaly recall ≥ 0.60。
- 主要結果提供 95% 信賴區間或多次實驗 mean／std。
- P95 模型推論延遲與端到端回應延遲均須實測。
- fusion 模型若未優於簡單基準，仍須完整解釋原因與限制。
