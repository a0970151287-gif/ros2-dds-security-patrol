`models_hier` 的所有數字都是在**校驗和損壞的網路特徵**上算的

這幾個被引用過的值，因此都要在修正後的表上重來。

但那是**操作點移動**，不是可分性變差，見第三節。

## 一、Enforce：乾淨的改善

```
舊：{unknown 1233, replay_dos 108, replay 50, normal 39, message_dos 6,
     parameter_tamper 3, command_injection 1}
新：{unknown 1314, normal 126}
```

**被自信誤填成已知類別的從 168 列變成 0。** 這是 open-set 最重要的失效方向
——C2C-026 就是因為「231 列被自信地誤填成已知類別」才把 0.7627 降為 0.5499。
在 Enforce 上這個失效現在完全消失了。

同時 recall 上升、正常誤判下降，兩個軸向都改善。

## 二、Permissive：數字掉了，但不是可分性掉了

```
舊：{unknown 418, parameter_tamper 251, normal 28, replay_dos 24, replay 1}
新：{unknown 152, parameter_tamper 344, replay_dos 203, normal 23}
```

判為未知的從 418 掉到 152，同時**正常誤判也從 2.75% 減半到 1.29%**。
兩個都往「更保守」的方向移動——這是門檻落在不同位置的樣子，
不是分離度變差的樣子。直接比 recall 不公平，因為操作點不同。

## 三、用 family-LOO 分開「可分性」與「操作點」

LOO 協定每一折重新擬合 binary／normality／attack-OOD，被抽掉的家族完全不進
擬合與門檻選擇，**官方 holdout 與 test 全程不碰**。它比的是可分性本身。

`工具腳本/diagnose_gate_veto.py`，Permissive，三折：

| 評分器 | OOD 頭上限（舊 → 新） | 整個模型 @normality 0.02（舊 → 新） |
|---|---|---|
| isolation_forest（出貨預設） | 0.2125 → **0.2253** | 0.1806 → 0.1251 |
| mahalanobis | 0.7839 → **0.7946** | 0.3690 → **0.4784** |

**OOD 頭的上限兩個評分器都上升。** 可分性沒有變差，反而略好。

掃 normality 預算看得更清楚（Mahalanobis）：

| normality 預算 | 舊表 | 封包表 |
|---:|---:|---:|
| 0.02 | 0.3690 | **0.4784** |
| 0.05 | 0.4217 | **0.5665** |
| 0.10 | 0.5428 | **0.6793** |
| 0.20 | 0.5451 | **0.7652** |

**封包表在每一個預算上都比較好。** 出貨預設 `isolation_forest` @0.02 是唯一
變差的組合，原因是新表的 normality 參考收得更緊（被否決佔比 0.1441 → 0.4749），
於是 gate 丟掉更多 OOD 頭認對的列。

## 四、一個可以寫進論文的張力，現在兩邊都量到了

同一次特徵修正，對兩個模式的效果**相反**，而原因是同一個：

| | 閉集識別 | 對未見類別的行為 |
|---|---|---|
| **Permissive** | 0.8823 → **0.9243**（大幅提升） | 自信誤填**惡化**（251 → 344 列 `parameter_tamper`） |
| **Enforce** | 0.4674 → 0.4892（仍然很低） | 自信誤填**消失**（168 → 0 列），open-set 0.9125 |

**分類器越確信，就越自信地把沒見過的東西塞進已知類別。**
Enforce 的分類器分不出類別，所以它「不敢」亂填，反而 open-set 表現最好。

這不是巧合，是 open-set 的結構性張力。先前只在 Permissive 一側觀察到；
這次的特徵修正讓兩側**同時**動，而且方向相反，等於一個天然的對照。

## 五、進度不動，理由

未知攻擊那一格維持 **70%**：

- 引用的 0.9543 是**原 holdout ＋ Mahalanobis**，而原 holdout 已被重複使用。
  這次又在新表上用了一次，累積曝光更多，不宜再拿它加分。
- **處女 holdout（`command_injection`／`identity_abuse`）沒有重跑。**
  它在整個模型層級已經用過兩次，第三次沒有可信度（C2C-042 的判斷未變）。
  跨類別的泛化**仍然未獲證明**，那才是這一格卡住的原因。
- 出貨預設仍是 `isolation_forest`，一個字都沒改。
