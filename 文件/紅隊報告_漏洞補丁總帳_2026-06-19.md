## 2. 本輪實際改動的檔案

### A. F1-b 參數鎖（app 層，新）
- `src/.../monitor_node.py`：新增 `SECURITY_LOCKED_PARAMS` + `lock_sensitive_params(node, extra)`。
- 套用 6 節點：monitor / patrol / mission_manager / sensor_hub / system_status / intelligent_defense。
- **驗證**：runtime test 模擬攻擊者 `set_parameters(use_sim_time=True)` → `successful=False`、`reason="use_sim_time is security-locked (F1-b)"`、值維持 `False`。✅
- **為何重要**：`use_sim_time=true` 又無 `/clock` → 該節點所有 wall-clock timer 凍結（心跳停、巡邏停）＝對單一節點 DoS。

### B. 隱形 DoS 偵測（Zeek，新）
- `Zeek監控/dds_monitor.zeek`：新增 `TRUSTED_DOS_THRESHOLD=60`、`check_trusted_dos()`、`trusted_dds_times`。
- 補的破口：原本 `new_connection` 對 `TRUSTED_DDS_HOSTS` 直接 `return`，F7-D 全偽造成 10.10.10.2+合法MAC 後灌 SPDP → 同時繞過 raw_packet（IP+MAC 都對）與一般 DoS（被早退）。現在信任來源也監看速率，飆破 60/8s（正常 ~15）即告警「疑似來源偽造的隱形 DoS」。
- **誠實標注**：這是**網路層速率啟發式**，能抓「全偽造+洪水」，但抓不到「全偽造+低速精準注入」——後者只有 Enforce 身分驗證能根治（告警文字已寫明）。

### C. 控制鏈 Enforce 明確化（政策）
- `展示指令/sros2_policy.xml`：`/gazebo` enclave 補上 `ros_gz_bridge`、`robot_state_publisher` profile，並加註解說明 /cmd_vel 訂閱端（bridge）受 Enforce 保護的原理（enclave 憑證層 wildcard 授權）。
- 改政策後若要讓既有 keystore 生效，需重跑 `bash 展示指令/10_SROS2啟用.sh` 重新產 permissions（wildcard 下功能等價，主要差在 node-relative 名稱展開更精確）。📋

### D. governance 現況（已就緒，無需改）
實查 `sros2_keystore/enclaves/governance.xml`（domain 30）：
```
allow_unauthenticated_participants = false
enable_join_access_control        = true
discovery_protection_kind         = ENCRYPT
liveliness_protection_kind        = ENCRYPT
rtps_protection_kind              = SIGN
metadata/data_protection_kind     = ENCRYPT
```
→ 這組設定即為 §6 Round5（DATA(p)/HEARTBEAT 偽造）的根治：未認證者偽造的 RTPS 無有效簽章 → 被丟。（可選硬化：`rtps=SIGN`→`ENCRYPT` 加機密性，但抗偽造 SIGN 已足。）

## 3. 誠實的固有限制（紅隊報告也認同的）

1. **明文網路層只有 IP/MAC 可信** → F7-C 假歸因、F7-D 全偽造的「身分」面，Zeek 無法根治；根治＝Enforce 加密後用**已驗證身分/GUID** 做交叉檢查（紅隊 §5 建議 3、報告 §2⑤D 自己也寫「需 SROS2 根治」）。
2. **網路層 SPDP 洪水無法 100% 消除** → 封包仍到網卡耗少量 CPU；L1 限流 + Discovery Server 是削到無害，不是消失。
3. **Zeek 不重組 RTPS DATA_FRAG** → 內容類偵測（注入簽章 / set_parameters）可被分段規避；非內容類（偵察/DoS/F7/隱形DoS）不受影響。要根治內容類規避＝Enforce 加密（攻擊者根本送不進來）。
4. **WSL2 mirrored 模式** → host iptables 可能不攔鏡像流量，L1/L2 阻斷要改用 Windows 端防火牆（見 DoS_DDoS防禦策略.md）。
