## 決定一：`blind` 不進訓練閘

**理由（摘自 C2C-098／099 的量測）：**

- 113／113 的持證內鬼場次是盲打的 ⇒ 判它不合格會**整個刪掉兩個類別**，
  Enforce 從 20 類掉到 18，而持證內鬼是這個專題的核心貢獻之一。
- 閘的職責是排除**證據不完整**的場次。盲打場次的證據是完整的——攻擊執行了、
  防禦反應了、遙測與 pcap 都在。缺的是攻擊者的**適應**，那是攻擊的性質，
  不是紀錄的缺陷。
- 盲打本身是**威脅模型在正確運作**：偷到節點 X 憑證的人不可能同時是 `n37_probe`。

**已做的替代**：`manifest.result.adaptive_observer` 逐場記錄（三值、不進閘、
永不拋），`工具腳本/audit_adaptive_blindness.py` 對既有場次唯讀推導，
而兩處「自適應攻擊者」的無限制宣稱已加上量到的限制。

⚠️ **這個決定要留著不被重新打開**，所以它寫在這裡而不只在訊息紀錄裡。
`tests/test_adaptive_blindness_recorded.py` 的
`test_blindness_is_not_a_gate_condition` 與
`test_the_gate_still_has_exactly_its_six_conditions` 釘住它。

## 決定二：gate 不移植到 `session_aggregate`

**理由：**

- 移植會改變 `deployment_eligible` 的**意義**：那 0.80 的門檻是為**逐視窗**表述
  校準的，而 C2C-059 已記過「場次層級與視窗層級是不同的任務」。
- 而 gate **不是現在的約束**：campaign 跑完只翻 11 道裡的 **1 道**
  （`minimum_1100_independent_sessions`），三道結構性地擋住
  （類別覆蓋差 3 支 runner、separability 是已量到的否定、跨主機那條鏈）。
  移植的工作買到的是「一個仍然不能部署的模型的 gate 判定」。

**替代：各自在自己的框架裡跑，兩個數字都標明框架。**

## 重訓那天的順序

⚠️ **前提**：campaign 跑完（或停在一個決定好的場次數），而這四個階段的
**順序不可調換**——第一階段必須在任何東西讀過 holdout **之前**。

### 第 0 階段：抽特徵（一次）

```bash
python3 -m firewall_lab.features \
    --dataset ~/dataset_mega --output ~/features_mega \
    --network-source packet \
    --exclusions firewall_lab/dataset_exclusions.v1.json
```

⚠️ `--network-source` 是**必填**（C2C-050：兩種基底欄位相同、意義不同，
選錯不會有任何徵兆）。`packet` 是修正後的逐封包分窗。

⚠️ 它對「有 pcap 卻沒有 `packet_windows/packets.tsv.gz`」是 fail-closed 的。
2026-10-03 稽核 3,933 場缺檔 0，但 campaign 之後會有新場次——先跑
`工具腳本/audit_adaptive_blindness.py` 之外，再確認一次覆蓋。

### 第 1 階段：**先封印，四份**

```bash
# 識別那一半（split == test）
python3 工具腳本/seal_holdout.py seal --scope test \
    --features ~/features_mega/fusion_features_permissive.csv \
    --registration 文件/重訓預先註冊_2026-09-27_r4.json \
    --output 文件/封印_識別_permissive.json
# 未知攻擊那一半（novelty_role == novelty_holdout_candidate）
python3 工具腳本/seal_holdout.py seal --scope novelty_holdout \
    --features ~/features_mega/fusion_features_permissive.csv \
    --registration 文件/重訓預先註冊_2026-09-27_r4.json \
    --output 文件/封印_openset_permissive.json
```

enforce 兩份同理 ⇒ **共四份**。兩個 scope 是正交的（實測交集 6／40），
所以兩個封印並存而互不擋住。

⚠️ **這一步必須最先做。** 封印是對「那個時候的 holdout」的承諾；
在任何評估器讀過之後才封，封的就是一個已經被看過的東西。

### 第 2 階段：識別（`session_aggregate`，2026-09-16 選定的表述）

```bash
python3 工具腳本/retrain_from_registration.py \
    --registration 文件/重訓預先註冊_2026-09-27_r4.json \
    --seal 文件/封印_識別_permissive.json \
    --features ~/features_mega/fusion_features_permissive.csv \
    --output 文件/重訓_識別_permissive.json
```

⇒ **這是可引用的識別率**：處女 holdout、`session_aggregate` ＋ RandomForest ＋
`d1_m3_x3` ＋ `full`，四項與註冊逐字相符。enforce 同理。

### 第 3 階段：未知攻擊（hierarchical parallel gate，註冊的 OOD 設定所在的線）

```bash
# open-set 評估器要 hierarchical 線的 training_metrics
python3 -m firewall_lab.hierarchical_training \
    --features ~/features_mega/fusion_features_permissive.csv \
    --output ~/models_hier_mega/permissive
python3 工具腳本/evaluate_openset_from_registration.py \
    --registration 文件/重訓預先註冊_2026-09-27_r4.json \
    --seal 文件/封印_openset_permissive.json \
    --features ~/features_mega/fusion_features_permissive.csv \
    --metrics ~/models_hier_mega/permissive/training_metrics.json \
    --output 文件/未知攻擊_封印holdout_permissive.json
```

⇒ **這是可引用的 open-set recall**：`max_softmax` ＋ k-of-n（k=2），
兩者都在**新資料存在之前**凍結進註冊。

⚠️ **Enforce 會被拒絕**，而那是正確的：r4 的 `ood_scorer_enforce` 是
`undecided`，因為 C2C-088 把 3 個評分器 × 8 種池化共 24 格掃完，
`worst_family_unknown_recall` 全部是 0.0000 ⇒ 那個選擇在宣告的格子裡
不可能有影響。

### 第 4 階段：gate 判定——**而且不要帶 `--final-evaluate-test`**

```bash
python3 -m firewall_lab.grouped_training \
    --features ~/features_mega/fusion_features_permissive.csv \
    --output ~/models_final_mega/permissive_fusion \
    --feature-set fusion --data-tier live
```

### ⚠️ 這一階段是把 runbook 寫具體才發現的衝突

我原本說「跑兩條路」。但 `grouped_training --final-evaluate-test` **也會讀
test split**，而識別那一半的封印綁的正是 `split == test`
⇒ **帶那個旗標會把識別 holdout 用第二次。**

正確的做法是**不帶它**，而那比我原本的建議更乾淨：

| gate | 不帶 `--final-evaluate-test` 時 |
|---|---|
| `live_data_tier`、`fusion_feature_contract`、`session_split_overlap_zero` | ✅ 照樣判定 |
| **`minimum_1100_independent_sessions`** | ✅ 照樣判定——**而這正是 campaign 唯一會翻的那一道** |
| `all_policy_classes_present`、`validated_live_multimodal_contract` | ✅ 照樣判定（都是結構性的否定） |
| 四道品質 gate（BA／macro F1／unknown recall／anomaly FPR） | **False，未評估** |
| `final_test_evaluated_once` | **False** |

⚠️ **上表是量到的不是推的**：`models_refresh_enforce` 那一輪就是沒帶旗標的，
而它的 `training_metrics.json` 裡十一道 gate 全部產出、六道結構性的真的被判定
（3 True／3 False）。

那四道品質 gate 的門檻是**逐視窗校準**的，所以即使評估了也必須加免責
（C2C-059：兩個粒度不可比），而代價是**把識別 holdout 燒第二次**。
⇒ **評估它們買到的是一個要被免責的數字，付的是唯一一次開封。不要。**

**所以第 4 階段產出的是「結構性 gate 的判定」，而可引用的品質數字來自
第 2、3 階段。** 兩個數字各自在自己的框架裡，誰都不假裝是另一個。

## 不可宣稱

- **這個順序還沒有整條跑過。** 第 2、3 階段各自演練過（C2C-091、C2C-099，
  都用已花掉的 holdout），第 0、4 階段沒有在新資料上跑過。
- 第 4 階段那句話**已經經驗驗證**，不只是讀程式。C2C-024 記過 `models_refresh`
  那一輪只跑 validation、沒帶 `--final-evaluate-test`，而它的產物就是答案：

  ```
  models_refresh_enforce/training_metrics.json
  ```
