## 現況

兩個正式模型都 `deployment_eligible=false`。十一道 gate 裡八道綠、三道紅:

```
❌ all_policy_classes_present
❌ minimum_1100_independent_sessions
❌ validated_live_multimodal_contract
✅ live_data_tier            ✅ fusion_feature_contract
✅ final_test_evaluated_once ✅ session_split_overlap_zero
✅ anomaly_normal_fpr_at_most_0_05
✅ test_balanced_accuracy_at_least_0_80    （Permissive）
✅ test_macro_f1_at_least_0_80             （Permissive）
✅ unknown_holdout_recall_at_least_0_70    （Permissive）
```

**三個紅燈沒有一個是模型品質問題。** 品質那三道 Permissive 全部通過。

## 一、我先更正自己的一個說法

我在 2026-09-01 稍早向 Jesse 說 `validated_live_multimodal_contract`
是「設計上永遠紅燈的 gate」。**那個說法不精確。** 查了實際的 blocker 文字:

> the security mode must be shown to be unrecoverable from the network features
> alone (`firewall_lab.mode_leakage`). **The pilot cannot answer this: Enforce
> covers two scenarios and Permissive nine**, so the gate correctly refuses to
> score rather than measure scenario differences and report them as a pass.
> **It needs paired sessions from the formal campaign, which is what this
> blocker is waiting for.**

它不是永遠紅燈,**是過期了**。它在等的那批成對資料 **2026-08-13／14 就跑完了**
（1,100 場,Permissive／Enforce 各 550）,而且給了明確答案:

| | 值 |
|---|---:|
| 跨模式可分離度 | **0.9451** |
| 契約門檻 | 0.70 |

**這個 gate 問了一個問題,問題已經被回答,答案是否定的**——安全模式**可以**
從網路特徵還原。contract 從來沒有被更新去記錄這件事,所以它的 blocker 文字
現在是事實錯誤的:它說在等一批已經到了一年多前的資料。

## 二、三個紅燈裡有兩個是同一個量測的下游

```
  gate 3 問「模式可不可以從網路特徵還原?」
      ↓  1,100 場成對資料回答:可以,0.9451
  ⇒ 不能用單一 pooled 模型（會學到模式而不是攻擊）
      ↓  因此改採分模式訓練
  ⇒ 每個模式只剩 550 場
      ↓
  gate 2「至少 1,100 個獨立 session」變成不可能達成
```

`MIN_DEPLOYMENT_SESSIONS = 1100` 這個常數是**為 pooled 模型寫的**。
分模式是 gate 3 的答案**逼出來的**,而分模式又讓 gate 2 永遠紅。

**兩個紅燈追溯到同一次量測。** 這不是「模型還不夠好」,是驗收標準寫在
架構改變之前。

## 三、第三個紅燈:類別覆蓋

`all_policy_classes_present` 要求 `set(模型類別) == set(policy 的 23 條)`
**完全相等**。目前的覆蓋:

| 來源 | 類別數 | 內容 |
|---|---:|---|
| 出貨 catalog 現在可產生 | **12** | 含 2026-09-01 新增的 `hmac_forgery`、`confused_deputy` |
| 候選 runner 可再補 | +7 | `baseline_poisoning`、`cross_channel_relay`、`health_spoof`、`mission_spoof`、`node_name_evasion`、`scan_drift`、`verify_flood` |
| **完全沒有 runner** | 4 | `cmd_vel_race`、`node_churn`、`odom_spoof`、`spdp_flood` |

所以上限是 **19／23**,而 gate 要 23／23。這一格是可以逐步推進的
（9 → 12 已經發生),但**在寫出那 4 個 runner 之前不可能綠**。

⚠️ 這一格與前兩個不同:**它是真的還沒做完**,不是標準寫錯。
