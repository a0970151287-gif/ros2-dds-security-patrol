## 二、⚠️ 這是修正後的第一次，不是「一直都能跑」

2026-09-21 的第一次 live 執行**沒有產出報告**，它在第四項檢查就崩了。那一輪與
後續的離線重演一共找到**五個缺陷**，其中三個會讓正式 backend 在**任何真核心上
一律拋錯**：

| # | 缺陷 | 為什麼離線看不到 |
|---|---|---|
| 1 | `sudo` 的 `env_reset` 剝掉 `SSH_CONNECTION`，防鎖死閘變 no-op | 只有真的用 `sudo` 執行才會發生 |
| 2 | 規則契約寫 `"op": "in"`，真核心渲染成 `"=="` | 假 runner 餵的是同一個錯常數 |
| 3 | 規則契約寫 `{"counter": None}`，真核心是 `{"packets":0,"bytes":0}` | 同上 |
| 4 | set／element 的 timeout 被當**毫秒**讀，其實是**秒** | mock 也乘了 1000，兩邊一起錯 |
| 5 | `reconcile()` 對到期時間做**奈秒精確比對** | `InMemoryTimeoutSetAdapter` 存什麼回什麼，精確比對天生成立 |

第 4 個最危險，因為它的錯法是往「**以為自己還在保護**」的方向：12 秒的封鎖會被
記成 12,000 秒過期，核心 12 秒後放行，而 backend 的狀態要三個多小時後才認為
到期。

共同形態與本專案記過的十五次一樣，只是換了位置：**假的 runner 與正式程式共用
同一個錯誤假設，所以它們只是彼此同意。** 第 4 個尤其清楚——把 mock 的單位改了
1000 倍，**沒有任何一個既有測試動搖**，因為從來沒有人斷言過到期時間。

修正全部用**真核心錄下來的 fixture** 釘住（`nft -j` 的逐字輸出，不是從程式推導
的），另加一支離線重演用假 runner 走完整條票的建構——第 5 個就是它抓到的，
沒有再花一次 live。

## 三、防鎖死閘改成不依賴環境變數

原本讀 `SSH_CONNECTION`，而 `sudo` 會清掉它。真機實測：

```
as user   : SSH_CONNECTION=192.168.137.1 53128 192.168.137.2 22
under sudo: SSH_CONNECTION=            ← 空的
```

改成直接讀核心 socket 表（`/proc/net/tcp`／`tcp6`，只取 `ESTABLISHED` ＋ 本地埠
22），環境變數降為**附加**來源。這樣「沒有 peer」變成一個量測結果，不是一個
變數不見了。本次驗收的證據行 `source=proc-net-tcp(1)` 就是它在 `sudo` 底下
正常運作的直接紀錄。

修正前後的真機對照（同一條指令、同樣 plain `sudo`、拿 `.1` 當測試目標）：

- 修正前：被**預設路由**檢查擋下（防鎖死那道根本沒被執行到）
- 修正後：`BLOCKED: … holds an established SSH session to this host`

## 四、不可宣稱

- **兩道部署閘一個都沒動**：`LIVE_NFT_ACTIVATION_ALLOWED = False`、
  `production_source_gate = False`。這份報告產出的是一個 SHA-256；要啟用正式
  backend 還需要人工審過後把雜湊釘進 root 擁有的啟用檔，**再加一次獨立的
  原始碼審查**才准改那個常數。
- **一個測試來源、一張票、12 秒 TTL、同一條隔離鏈路。** 不是壓力測試、
  不是長時間 soak、沒有多來源、沒有併發。
- `packet_drop_verified` 只動了 **1 個封包**。它證明封包走了 drop 路徑，
  **不證明吞吐或多來源下的行為**。
- **這條鏈不是被偵測驅動的**。票是由驗收執行器自己簽發的，不是由模型判定產生
  的。`executable_classes` 仍是空清單 ⇒ **零個類別被授權執行**。
- 隔離前提是靠**暫時移除 Pi 的預設路由**達成的，那不是常態部署姿態。
- 既有 1,101 場的來源歸因仍是 0；這一輪沒有改變那件事。
